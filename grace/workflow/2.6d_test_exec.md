# Test Executor Agent

You run the cases designed by `2.6b_test_design.md` with the requests generated by
`2.6c_test_requests.md`, classify every failure, and own the **bug bucket** `{RUN_DIR}/test/bugs.json`.
You write mechanical driver scripts, you never edit cases, requests, repo files or assertions, and you
never decide a fix. A failure is either routed back to a test agent, to the environment agent, or
becomes a bug for `2.6e_rca.md`.

HS → UCS → connector (`hs_rest`, for unit `IncomingWebhook` `hs_webhook`; three-hop assertion of `grace/workflow/2.5_e2e.md` section
"Phase 4: Run the real payment") is the primary gate; `ucs_grpc` covers what HS cannot construct.

---

## Inputs

| Parameter | Description | Example |
|-----------|-------------|---------|
| `{RUN_DIR}` | Run directory | `grace/runs/braintree-a1b2c3/` |
| `{ROUND}` | Round number `N`, unique per executor spawn (ONLY_CASES re-runs get a new N) | `3` |
| `{MODE}` | `FULL_RUN` (every `live` or `sandbox_blocked` case) \| `ROUND` (ONLY_CASES, else every case whose latest verdict is not PASS) | `ROUND` |
| `{ONLY_CASES}` | Optional: comma-separated case ids, a path to a JSON array of ids, or `none` (bookkeeping only: Phases 0, 1, 6, 7, 8 and the Phase 3 `lib.sh`, without execution, no `r<N>.json`). Never combined with `MODE: FULL_RUN`; if it is, `MODE` wins — run the full set, decision row | `refund_happy_hs,rsync_id_consistency` |
| `{INGEST}` | Optional, comma list of `baseline` (`test/baseline_bugs.json`), `review` (`review/findings.json` S0/S1, `status` open), `spec_gaps` (`test/cases.json` `spec_gaps[]` with `status: "open"`) | `review` |
| `{STATUS_UPDATES}` | Optional path to a status-update file written by the orchestrator (schema below) | `{RUN_DIR}/test/status_updates/u7.json` |
| `{POLL_INTERVAL_S}` / `{POLL_MAX_S}` | Async poll tuning (defaults 5 / 120) | `5` / `120` |

Reads: `run.json` (units, caps, counters, base_sha), `env/env.json`, `test/capabilities.json`, `test/cases.json`,
`test/requests/*.json`, `test/final.json` and `test/select/not_run.json` (if present), `~/.local/state/grace/<run_id>/secrets.env`
(`<run_id>` = basename of `{RUN_DIR}`), the creds file at `preflight.json .creds.path` (resolved by 2.0; never
re-resolved), `env/load_secrets.sh` (named in `2.6c_test_requests.md`).

## RULES

1. **Never waive.** No `assert: null`, no dropped or widened assertion, no negative override (asserting
   failure to make a case pass). A case with no assertions is `TEST_DESIGN_WRONG` rule `no_assertions`.
2. **Read-only on inputs.** Never edit `cases.json`, `requests/`, `crates/**`, `connector_specs/**`,
   creds or the HS worktree. You append nothing to `claimed.tsv`. Git: read-only commands only.
3. **Sole writer** of `test/bugs.json`, `test/final.json`, `test/results/**`, `test/driver/**`. Every file: write
   `<path>.tmp`, then `mv`. Never write `test/evidence/**` (2.6a owns `test/evidence/baseline/**`).
4. **No secret ever lands in `{RUN_DIR}`.** Headers keep `${NAME}` placeholders in scripts and transcripts;
   values are expanded only in the calling process (`grpcurl -expand-headers`, `curl -H @<(…)`; Phase 3 Render).
   Every stored response, log excerpt and harness report is redacted (Phase 4d).
5. **Caps** come only from `run.json` `caps` (copied from `grace/workflow/2_connector.md` "## Caps").
6. **Harness defects are notes, not bugs.** Record `harness_notes[]` and re-run the case with direct grpcurl.
7. **SANDBOX_BLOCKED needs two agreeing sources**: `capabilities.json` says `not_provisioned` AND this round's live
   connector response agrees (Phase 5 row 5).
8. **Process ownership**: never start, stop or kill servers; a dead UCS/HS is `ENV` (2.6a REPAIR).
9. **Autonomous.** Every judgement (oracle comparison, unit mapping, class choice) is a row in
   `test/results/r<N>.decisions.md` (bookkeeping-only: `test/bugs.decisions.md`), a table
   `| Decision | Options considered | Chosen | Why | Evidence / source |`.

## Phase 0: Preconditions

```bash
test -f {RUN_DIR}/test/results/r{ROUND}.json && echo ROUND_EXISTS          # → STATUS FAILED
mkdir -p {RUN_DIR}/test/results && touch {RUN_DIR}/test/results/.r{ROUND}.start   # Phase 8 gate stamp
for f in env/env.json test/cases.json; do test -f {RUN_DIR}/$f || echo "MISSING $f"; done
[ "{ONLY_CASES}" = none ] || test -f {RUN_DIR}/test/requests/index.json || echo "MISSING test/requests/index.json"
CREDS=$(jq -r '.creds.path // empty' {RUN_DIR}/preflight.json); [ -r "$CREDS" ] || echo "MISSING creds"   # fail closed
UCS_PORT=$(jq -r .ucs.port {RUN_DIR}/env/env.json)
grpcurl -plaintext localhost:$UCS_PORT grpc.health.v1.Health/Check          # expect "status": "SERVING"
kill -0 "$(cat {RUN_DIR}/env/ucs.pid)"
```
HS base URL/health check, log paths and the `test_ucs` binary also come from `env/env.json` (schema: `2.6a_test_env.md` "## Output").
Missing `env.json`/`cases.json`/readable creds, or `index.json` (execution spawns) → `FAILED`, `REASON: MISSING <file|creds>` (no creds = no 4d needles:
nothing runs or is written); UCS not SERVING before the first case → `BLOCKED`
`REASON: ENV` (no results written). Optional inputs: `test/capabilities.json` absent (BASELINE failed or timed out) →
no case can be `SANDBOX_BLOCKED` this round (Rule 7), decision row. A selected case with no
`test/requests/<case_id>.json` (open-gap cases excepted: Phase 2) → outcome `NOT_RUN`, listed in `test_suspect.design`
if `index.json .unrenderable` names it, else in `test_suspect.request` (at cap: Phase 5 **At cap**); decision row.
Verify once per round that UCS JSON log lines carry the request id: after the first executed `ucs_grpc` case,
`grep -cF "$RID" {RUN_DIR}/env/ucs.log`; 0 hits → decision row and `link: time_window` for the whole round.

## Phase 1: Bookkeeping (INGEST, STATUS_UPDATES)

Load `test/bugs.json` (or `{rev:0,bugs:[]}`). Apply in order:

**a. INGEST.** `baseline`: every item of `test/baseline_bugs.json` (bug object shape below, minus
`bug_id/status/history`) → `source: baseline`, `pre_existing: true`. `review`: each `review/findings.json`
item with `sev` S0|S1 and `(.status // "open") == "open"` (fixed items are skipped) → `source: review`, `review_ref: <finding id>`, `category: review_claim`, `severity: <sev>`,
`blocking: true`, `pre_existing: false`, `surfaces: [static]`, finding units = its `units`, else the units whose
`code/*.json` `files_modified` contains `file` (`hs:<path>` → `__hs__`), `in_scope` = a finding unit is a `run.json` unit
or `__hs__`, `flows` = markers of the finding units (`__hs__`: of the `flows_unblocked` of the `plan.json .hs_changes[]`
items its `parity_ref` names, else of every run unit),
`evidence: [{kind: code, ref: "file:line", excerpt: claim}]`, `expected.value: observable_consequence`,
`error_class: <file>` (no line). `spec_gaps`: each `cases.json` `spec_gaps[]` with `status: "open"` → `source: spec_gap`,
`category: spec_gap`, `gap_ref: <gap_id>`, `cases` = its `case_ids`, `error_class: gap:<gap_id>`, `msg` = `question`,
severity S1 if it blocks a happy case else S2. `spec_gaps` also runs on every spawn without the flag, for open gaps
no bug's `gap_ref` names yet (gaps a later 2.6b AMEND added). Every ingested item not merged in b gets the next
`bug_id`, `status: open`, `attempts: 0`, `duplicate_of: null`, history `created`.
**Resolved gaps** (every spawn, INGEST or not): a bug whose `gap_ref` gap is now `status: "resolved"` and whose status is
in the Phase 7 open set → `fixed`, history `status` note `gap <gap_id> resolved_by <resolved_by>` (own bookkeeping, not a
STATUS_UPDATES transition).

**b. Dedupe** by fingerprint (Phase 6): same fingerprint → merge `cases/flows/surfaces/evidence` (keep the
latest 5 evidence items) + history `merged`. Existing status `fixed` → `open`, history `reappeared`.
Existing `invalid|wont_fix|flaky` → status kept, history `seen_again`.

**c. STATUS_UPDATES** — file shape (orchestrator writes, you apply):
```
[{update_id, bug_id, to: rca|fixing|retest|fixed|unresolved|wont_fix|invalid|flaky|open,
  by: <stage id>, ref: <path, e.g. rca/r3.json or rca/briefs/b3-01.json>, reason,
  set: {pre_existing?, severity?, in_scope?, cluster_key?, duplicate_of?}}]
```
Skip an `update_id` already in the bug's history. Allowed transitions: `open→rca`, `rca→fixing|invalid|flaky|unresolved|wont_fix`,
`fixing→retest|unresolved`, `retest→fixed|open` (open = failed fix), any non-terminal → `unresolved|wont_fix`,
`fixed→open` (reappearance). Entering `fixing` increments `attempts`. A disallowed transition is not
applied: history `rejected_update` + decision row.

## Phase 2: Select cases and build chains

1. Case set: `FULL_RUN` → every case with `provokability` ∈ {`live`, `sandbox_blocked`}, **minus** every case whose
   unit is `plan/plan.json .order[] | select(.status == "withdrawn") | .unit` (that flow is `not_implemented` again;
   re-running it would file bugs RCA then routes into re-implementing it — `select_cases` subtracts the same set);
   `ROUND` → ONLY_CASES, else every case whose
   `final.json` outcome is not `PASS`. Add every transitive `depends_on` prerequisite (always re-run: binds
   must be fresh). `unprovokable` → outcome `SKIPPED_UNPROVOKABLE`; in the `case_ids` of a `status: "open"`
   `spec_gaps[]` entry → `SKIPPED_SPEC_GAP` (2.6c renders no request; its INGEST bug covers it; never a suspect),
   dependents `BLOCKED_BY_DEP`, decision row; `sandbox_blocked` in cases.json → run it anyway (Phase 5 decides).
   `env.json .hs.available` not true → every `hs_rest`/`hs_webhook` case is not executed: outcome `NOT_RUN`, no
   `env_issues[]` entry, never a suspect, decision row `HS_ENV:<unavailable_reason>` (Phase 7 `e2e_status` stays
   fail-closed); dependents `BLOCKED_BY_DEP`. A case in `test/select/not_run.json` (orchestrator: its test-agent AMEND
   failed, `2_connector.md` "### Test lane — `2.6b_test_design.md` → `2.6c_test_requests.md` (background after S3;
   foreground for later AMENDs)") → same treatment, decision row `TEST_AGENT_FAILED`, except on the final `FULL_RUN`,
   where it is an at-cap suspect instead of "never a suspect": upsert a bug `source: test`,
   `category: request_unrenderable`, `error_class: rule:test_agent_failed`, severity S1 when the case is
   `kind: happy` or a prerequisite of one, else S2 — otherwise the unit ends `FAIL`/`FAILED` with nothing in
   `test/bugs.json` to explain it and RCA has nothing to route.
2. Unit of a case: `case.unit` if present; else exact `<flow>/<dimensions.pm>` in `run.json` units; else
   `<flow>`; else the flow group whose markers (plan/plan.json) include `flow`. Record non-exact matches.
3. Chains = connected components over edges: `depends_on`, two cases consuming the same fixture id, two
   cases consuming a bind produced by the same case. Inside a chain, topological order (ties: case_id).
   Chains sharing a sandbox object are thereby serial.
4. Chain phase = its latest surface in `static → ucs_grpc → hs_rest → ucs_webhook|hs_webhook`. Pool: any
   `hs_*` case → HS pool (≤2 concurrent; when `env.json .hs.log` is null and `.hs.request_id_forwarded` is not true:
   1, run after that phase's UCS pool finishes, so a `time_window` link stays unambiguous), else UCS pool (≤4 concurrent). Name `c<nn>-<first case_id>`.

## Phase 3: Write driver scripts

Write `{RUN_DIR}/test/driver/r<N>/lib.sh` and one `{RUN_DIR}/test/driver/r<N>/<chain>.sh` per chain (round-scoped:
never overwrite an earlier round's drivers; bash + grpcurl + curl + jq, `set -uo pipefail`, no judgement inside).
Contract (also used by `2.6e_rca.md` for live re-runs and probes):

- Env: `TRANSCRIPT_ROOT` (default `{RUN_DIR}/test/results/r<N>/transcripts`), optional `UNTIL_CASE` (stop after it).
  `bash lib.sh run_request <request file>` runs one request outside any chain (no binds); `. lib.sh` with no
  arguments only runs Setup and defines functions (Phase 8).
- Setup (lib.sh, repo root): `. {RUN_DIR}/env/load_secrets.sh`; `CREDS` as in Phase 0, unreadable → exit 2 before any
  call or write (fail closed); `T=${UCS_GRPC_TIMEOUT_SECS:-60}` (per-call budget); export from `env/env.json` `UCS_PORT`=`.ucs.port`,
  `HS_BASE_URL`=`.hs.api_url`, `HS_MERCHANT_ID`=`.hs.merchant_id`, `HS_PROFILE_ID`=`.hs.profile_id`.
- Also written: `jobs.sh` = `long`/`waitx` copied verbatim from the `2.3b_codegen_unit.md` Setup block plus
  `DETACHED_WAIT_MIN=<run.json .caps.detached_wait_min>` (detached-job contract of `grace/workflow/2.0_preflight.md`
  "Phase 9: Background warm builds"), and one `<phase>.<ucs|hs>.list` per Phase 4 pool (chain names, one per line).
- Per case: attempt = 1 + highest existing `<attempt>.json` under `$TRANSCRIPT_ROOT/<case_id>/`.
- **Render** string leaves of `url`, `headers`, `payload`, `poll`, `webhook.body_template` with jq
  `walk(if type=="string" then … else . end)`, values read via `$ENV` / `--slurpfile` (never argv), in this order:

- Harness root: `SPECS_ROOT=$(jq -r '.harness.specs_root // empty' <request>)` — the root 2.6c staged, used as is

  .specs_src_sha` (codegen or `__promote__` edited the tree after staging) → its cases `NOT_RUN`, listed in

(`equals` | `must_exist` | `matches_ref` against the bind), `ucs.connector_http_call`, `hs.http_status`,
`hs.status_one_of`, `hs.three_hop` (all three of 2.5 Phase 4: `hs_routed_ucs`, `ucs_flow_logged`, real connector id).

**Async poll** (in-driver): only when actual status ∈ pending set (`PENDING`, `AUTHORIZING`, `CAPTURE_INITIATED`,

transitively depends on it is `BLOCKED_BY_DEP` (`blocked_by: <case_id>`), no transcript. PASS attempts are written
as `<attempt>.json`; FAIL attempts as `<attempt>.json.tmp` for Phase 5.

## Phase 4: Execute

Pools run detached under the detached-job contract of `grace/workflow/2.0_preflight.md` "Phase 9: Background warm
builds" (launch and join are separate calls; each join call passes `timeout: 600000`). Phases strictly in the order
`static ucs_grpc hs_rest webhooks`; for each `$PH`, first re-check UCS health (Phase 0 commands; not SERVING → stop,
remaining cases `NOT_RUN`, `env_issues[]`, `STATUS: PARTIAL`), then:
```bash
# call 1 (launch)
PH=<phase>; D={RUN_DIR}/test/driver/r{ROUND}; . $D/jobs.sh
long $D/$PH.ucs xargs -r -P 4 -a $D/$PH.ucs.list -I{} bash $D/{}.sh
long $D/$PH.hs  xargs -r -P 2 -a $D/$PH.hs.list  -I{} bash $D/{}.sh     # serial HS pool: launched after $PH.ucs.exit, -P 1
# call 2..k (join, one waitx per call)
PH=<phase>; D={RUN_DIR}/test/driver/r{ROUND}; . $D/jobs.sh; waitx $D/$PH.ucs
```
`TIMEOUT:<prefix>` → cases of that pool without a transcript `NOT_RUN`, remaining phases skipped, `STATUS: PARTIAL`,
REASON `TIMEOUT:<prefix>`. The next phase starts only when every `.exit` of this phase exists. A non-zero pool exit is
not a verdict (transcripts are); `<prefix>.log` is driver output.
Static phase: when `git status --porcelain -- crates/internal/integration-tests/src/connector_specs` is non-empty,
also launch the two sanctioned validators (the only `cargo test` allowed) with `long`, join them with `waitx` like the
pools, and record them as static evidence:
```bash
long $D/schema_scenarios cargo test -p integration-tests all_supported_scenarios_match_proto_schema_for_all_connectors
long $D/schema_overrides cargo test -p integration-tests all_override_entries_match_existing_scenarios_and_proto_schema
```

**4d Redaction** (lib.sh, applied before any write): build `name→value` (`secret_values`) with the needle rules of
`2.8_pr_run.md` "## Phase 4: Scrub and commit" 4a — values of `secrets.env` and string leaves of the connector's creds
entry (`creds.<path>`), skipping paths containing `_comment` or `auth_type` and `http(s)://` values, length ≥ 8 —
plus the base64 of each; pass it to jq via
`--slurpfile s <(…)` (never argv, never a file) and replace each value with `<redacted:NAME>`
(`split($v)|join(…)`). Header values of `authorization`, `api-key`, `x-api-key`, `x-key1`, `x-key2`, `x-api-secret`,
`x-connector-config`, `x-auth` not starting with `${` → `<redacted:header>`.

**Transcript** `{RUN_DIR}/test/results/r<N>/transcripts/<case_id>/<attempt>.json`:
```
{case_id, round, attempt, chain, driver: "test/driver/r<N>/<chain>.sh", unit, flow, surface, backend, driver_sha, started_at, ended_at, duration_ms,
 request:{target, method, headers{name: "${NAME}"|literal}, payload, request_id},
 response:{exit_code, grpc_code|null, http_status|null, headers_masked{}, body|null, raw_masked (≤200 lines)},
 signals:{invoke_error, transient, connector_http_call, ucs_flow_logged, hs_routed_ucs|null, status, error, ids{}, poll|null, harness|null},
 assertions:[{id, path, rule, expected, actual, pass}],
 ucs_log_ref:{file, link: request_id|object_id|time_window (+hs_log_unavailable), lines[], excerpt[≤20, redacted]},
 hs_log_ref:{…same}|null,
 outcome: PASS|FAIL, classification:{class, rule, route}|null, fingerprint|null, bug_id|null}
```
Log refs: `grep -nF "$RID" <log> | cut -d: -f1` → line numbers → `sed -n` those lines → `jq -c` → keep ERROR/WARN,
`Outgoing Request completed` and flow-naming lines, ≤20. `time_window` link = lines between started_at and ended_at
naming the connector.

## Phase 5: Classify each failed attempt (first match wins)

Harness backend first: harness panic, missing suite, or a dependency id the harness did not carry although the
upstream response contains it → `harness_notes[]` and re-run as direct grpcurl built from the latest block's
`req_body` (a new attempt); classify that attempt. `additional_dependencies` in `specs.json` does not exist;
suite dependencies live only in the global `suite_spec.json`.

## Phase 6: Bug bucket `{RUN_DIR}/test/bugs.json`

Rows 4 and 7, and rows 2 and 6 at cap (Phase 5 **At cap**), upsert a bug. Fingerprint:
```bash
norm() { tr 'A-Z' 'a-z' | sed -E 's/[0-9a-f]{8}(-[0-9a-f]{4}){3}-[0-9a-f]{12}/<id>/g; s/\b[a-z]{2,8}_[a-z0-9]{8,}\b/<id>/g; s/[0-9a-f]{16,}/<id>/g; s/[0-9]+([.,][0-9]+)?/<n>/g; s/[[:space:]]+/ /g' | cut -c1-200; }
printf '%s|%s|%s|%s|%s' "$surface" "$flow" "$category" "$error_class" "$(norm <<<"$msg")" | sha1sum | cut -c1-40
```
`error_class` = `grpc:<grpc_code>[/conn:<connector error code>]` | `http:<status>[/<HS error code>]` | `assert:<assertion id>`;
`msg` = the error message, else the first failing assertion's `expected≠actual`.
`category` (first failing assertion): `status_one_of`→`wrong_status`; `equals`→`wrong_field`; `must_exist`→`missing_field`;
`matches_ref`→`id_mismatch`; `connector_http_call`→`refusal_missing`; `error.class`→`wrong_error`; `three_hop`→`hs_unreachable`;
`http_status`→`http_status`; static `capability_parity`→`capability_mismatch`; plus `review_claim`, `spec_gap`,
`request_unrenderable`, `secret_in_log`.

**Schema** (`{rev, updated_at, bugs:[…]}`, each bug):
```
{bug_id: "B<nnn>", fingerprint, source: test|baseline|review|spec_gap, category,
 severity: S0|S1|S2|S3, blocking: severity∈{S0,S1}, pre_existing: bool, in_scope: bool,
 flows:[marker], surfaces:[ucs_grpc|hs_rest|ucs_webhook|hs_webhook|static], cases:[case_id],
 evidence:[{kind: transcript|ucs_log|hs_log|harness_report|code|doc|probe, ref, excerpt (≤20 lines, redacted)}],
 expected:{value, oracle_ref}, actual: "<one line, redacted>",
 status: open|rca|fixing|retest|fixed|unresolved|wont_fix|invalid|flaky,
 attempts: int, duplicate_of: bug_id|null, cluster_key: string|null, review_ref: <review finding id>|null, gap_ref: <gap_id>|null,
 history:[{at, round|null, by, event: created|merged|reappeared|seen_again|status|set|rejected_update, from, to, ref, update_id|null, note}]}
```
Severity (assign the highest that applies):
- **S0** money moved wrongly (status/amount shows CHARGED, AUTHORIZED, PARTIAL_CHARGED, captured or REFUND_SUCCESS where the
  case expects refusal/decline/failure or another amount; `connector_http_call: made` on a refusal case of a money-moving flow),
  security bypass (a guard such as 3DS skipped), secret leak (secret value in a response or UCS log).
- **S1** happy case fails; false capability (`capability_mismatch`, refusal on a declared flow); wrong terminal status;
  `id_mismatch` (id breaks downstream); `hs_unreachable` on an in-scope unit.
- **S2** wrong error class/code/message on a decline or refusal with no money movement; non-terminal status-arm mismatch;
  missing non-id response field.
- **S3** no observable effect (review/static only: naming, logging, style).

**Static HS reachability** (every spawn, bookkeeping included): a unit's **HS surface** is `hs_webhook` for unit
`IncomingWebhook`, else `hs_rest` (`2.6b_test_design.md` Phase 2 rule 1). Each run unit `$u` with `env.json .hs.available` true,
`cases.json .coverage.units[] | select(.unit == $u)` having `.hs_available` true and `.hs_reachable` false, and no case of
the unit on its HS surface → upsert a
bug `category: hs_unreachable`, `source: test`, `severity: S1`, `surfaces: [<HS surface>]`, `cases: []`, `flows` = the unit's markers, `error_class:
static:hs_reachable`, `msg` = `hs/scout.json .units[<unit>].gates_missing[].gate` joined by `;`, `evidence: [{kind: code,
ref: "hs/scout.json#units.<unit>.gates_missing", excerpt}]`, `expected: {value: "HS routes <unit> to UCS", oracle_ref:
"2.5_e2e.md Phases 1–3"}`. Its `retest → fixed` iff ≥1 case of the unit on its HS surface now PASSes with `three_hop: PASS`.

New test bug: `pre_existing` = fingerprint present in `test/baseline_bugs.json`; `in_scope: true`; `status: open`.
Retest transitions from this round (static `hs_unreachable`: rule above; `gap_ref` bugs also close via **Resolved gaps**):
a bug in `retest` has the set = its `cases` ∪ the `cases.json` cases whose `regression_for` contains its `bug_id`. A case
of the set fails (a `cases` entry with the bug's fingerprint, a regression case with any failure) → `open` (history
`status`, note `fix did not hold`; a failing regression case joins `cases`); else a non-empty set whose every case PASSed
this round → `fixed`; else (empty set, or a case not run or not PASS) → stays `retest`, decision row (`baseline`/`review`
bugs start with `cases: []`: they reach `fixed` only through the regression cases their RCA brief's `retest.add_cases`
had 2.6b AMEND add). A fingerprint matching a `fixed` bug → `open` + `reappeared`
(the orchestrator escalates via `2.6e_rca.md` PREVIOUS_ORIGIN). Case outcome `FLAKY` = its bug is `flaky`.

```
{rev, updated_round,

```

Derivation (cases of the unit, latest outcome; `SKIPPED_UNPROVOKABLE` and `SKIPPED_SPEC_GAP` excluded; a
`BLOCKED_BY_DEP` counts as its root's outcome):
- Unit bugs = bugs with a case of the unit or `flows` ∩ the unit's `plan/plan.json .units[].markers`. `open_bugs` = their
  `bug_id`s with status ∈ {`open`, `rca`, `fixing`, `retest`, `unresolved`} (the **open set**); `blocking_open_bugs` =
  those with `blocking: true` and `in_scope: true`.
- `grpc_status` over `static`, `ucs_grpc`, `ucs_webhook`: none run → `NOT_RUN`; all PASS → `PASS`; no FAIL/FLAKY and ≥1
  SANDBOX_BLOCKED → `BLOCKED`; else `FAIL`.
- `e2e_status` over `hs_rest`, `hs_webhook` (meanings: 2.5 "Phase 6: Report"; `E2E_SKIPPED` only when no HS exists):
  `coverage.units[] | select(.unit == "<unit>") | .hs_available` false or `env.json .hs.unavailable_reason` = `NO_CHECKOUT` → `E2E_SKIPPED`
  (reason `no HS: <unavailable_reason>`); `.hs.available` otherwise not true → `FAILED` (reason
  `HS_ENV:<unavailable_reason>`: a checkout exists, so the primary gate fails closed); no hs case and `hs_reachable`
  false → `E2E_BLOCKED` (reason `HS_UNREACHABLE:<gates_missing gates>`; its S1 `hs_unreachable` bug keeps the unit
  blocking); no hs case otherwise → `FAILED` (reason `NO_HS_CASE`, or `SPEC_GAP:<gap_ids>` when its hs cases are all
  `SKIPPED_SPEC_GAP`; decision row); ≥1 case on the unit's HS surface (Phase 6) PASS with `three_hop: PASS` and every hs case PASS → `SUCCESS`; no
  FAIL/FLAKY and ≥1 SANDBOX_BLOCKED → `E2E_BLOCKED`; else `FAILED`.

## Phase 8: Security exit gate

Write every output as `.tmp` first, then (file names only, never values):
```bash
. {RUN_DIR}/test/driver/r{ROUND}/lib.sh || exit 1          # defines secret_values; Setup exits 2 on unreadable creds
[ "$(secret_values | grep -c .)" -gt 0 ] || { echo 'SECRET_LEAK needles_empty'; exit 1; }   # fail closed
S={RUN_DIR}/test/results/.r{ROUND}.start
[ -d {RUN_DIR}/test/results/r{ROUND} ] && target/debug/check_report_creds --path {RUN_DIR}/test/results/r{ROUND}   # *.md (harness reports)
find {RUN_DIR}/test/results {RUN_DIR}/test/driver {RUN_DIR}/test/bugs.* {RUN_DIR}/test/final.* -type f -newer "$S" 2>/dev/null \
  | while IFS= read -r f; do grep -qF -f <(secret_values) -- "$f" && echo "$f"; done  # 1. files this spawn wrote: blocking
grep -rlF -f <(secret_values) --exclude=ucs.log --exclude=hs.log --exclude-dir=hs-wt --exclude-dir=workflow \
  --exclude-dir=.preflight --exclude-dir=warm --exclude-dir=disk {RUN_DIR}         # 2. rest of the run dir: recorded
grep -lF -f <(secret_values) {RUN_DIR}/env/ucs.log {RUN_DIR}/env/hs.log            # 3. logs
```
`secret_values` prints the Phase 4d values to the pipe only. A non-zero exit before the greps → `STATUS: FAILED`,
`REASON: SECRET_LEAK needles_empty` (lib.sh exit 2: `MISSING creds`); do not `mv`. Non-zero `check_report_creds` or any hit of 1 →
do not `mv`; `rm -f` every hit file (`check_report_creds`: each `.md` it names, plus that report's `report.json`) and
this spawn's `.tmp` outputs (every reference to a removed transcript lived in them), as `2.6a_test_env.md` Phase 7
item 5 does; `STATUS: FAILED`, `REASON: SECRET_LEAK <files>` (paths only, never the value). Hits of 2 outside those files are not
this spawn's leak: `security_gate.hit_files` + decision row (the owning stage's gate and 2.8 decide). A hit in
`env/ucs.log` → S0 bug `secret_in_log` (flows from the log lines), not a leak by this agent; a hit in `env/hs.log` → `env_issues[]`
(`hs_log_contains_secret`). Both are listed in `security_gate.log_hits`, so nothing downstream quotes raw logs.
Pass → `mv` `bugs.json`, `final.json`, then `r<N>.json` last.
