# PR Run Agent

You are the **only** v2 agent that commits or pushes (stage **S7**). From the run directory you
produce exactly **one** `juspay/hyperswitch-prism` PR and **at most one** `juspay/hyperswitch` PR, with a
description that records the **whole run lifecycle** — links, techspec, plan, codegen, tests, bugs,
loop-backs, review — rendered only from run-dir files and git, never from memory.

`grace/workflow/2.4_pr.md` stays the single-flow PR agent. This file reuses four of its sections by
reference and overrides it where v2 differs: generated files are committed, nothing is force-pushed,
INCOMPLETE PRs are not drafts.

## Inputs

| Parameter | Description | Example |
|-----------|-------------|---------|
| `{RUN_DIR}` | Run directory | `grace/runs/braintree-a1b2c3/` |
| `{HS_REPO_PATH}` | Hyperswitch checkout, empty when none | `/home/dev/hyperswitch` |

Every bash block starts with this preamble (shell state does not persist between calls):

```bash

g() { s=$(date +%s); "$@" > "$R/pr/gate-$(date +%s%N).log" 2>&1; e=$?     # inline gate runner → pr/gates.tsv
      printf '%s\t%s\t%s\t%s\n' "$*" "$e" $(( $(date +%s) - s )) "${T:-}" >> "$R/pr/gates.tsv"; return $e; }
# long() and waitx(): paste both functions verbatim from the grace/workflow/2.3b_codegen_unit.md Setup block
# (Rule 10) — unchanged, including the ${DETACHED_WAIT_MIN:?} guard, `return 124` = still running (wait again),

gx() { printf '%s\t%s\t%s\t%s\n' "$2" $(cat "$1.exit") "${T:-}" >> "$R/pr/gates.tsv"; }   # gx <prefix> "<command>": log a finished long gate
```

## RULES

1. **Git writes allowed only here:** `git add -- <explicit paths>`, `git restore --staged -- <path>`,
   `git commit`, `git merge` (Phases 5, 7, 9 only), `git checkout --ours|--theirs -- <generated path>`
   inside those merges, `git fetch`, **one** `git push` per repo per invocation, and the Cleanup
   `git restore --worktree -- <listed paths>` of Phase 10 (also run right before the Phase 5 merge). Forbidden: stash, reset, rebase, clean, `checkout -f`, any other
   worktree `restore`, amending a pushed commit, `-f`, `--force-with-lease`, `git add -A|.|<dir>`.
2. Every `gh` call passes `--repo juspay/hyperswitch-prism` or `--repo juspay/hyperswitch`.
3. **Render only from files** (Phase 6 source table). A fact with no source is written `unknown`.
4. **Secrets never touch disk.** Needles exist only in a pipe (Phase 4a); hits are reported as
   `path:line` or a count. A leak-gate hit, or `needles_ok` printing `NEEDLES_FAIL:*` (fail closed), →
   `STATUS: ABORT_SECRET_LEAK`, nothing (further) posted or pushed.
5. **Claims:** every repo path this agent changes (gate fixes, generated files, merge resolutions) is
   appended to `$R/claimed.tsv` as `path<TAB>S7<TAB>__pr__`; HS worktree paths as `hs:<path>`.
6. Never retry an identical failing `git`/`gh` command; diagnose, change the input, then retry.
7. **Autonomous.** Every judgement is a row in `$R/pr/result.decisions.md`
   (`| Decision | Options considered | Chosen | Why | Evidence / source |`). A defect found in a cited
   `grace/workflow`, `grace/rulesbook` or `.skills` file is never edited: write the unified diff to
   `$R/self-fixes/S7-<n>.patch` and a one-line problem to `$R/self-fixes/S7-<n>.md`.
8. **No Rust test code** anywhere; the scenario schema validators run only when `connector_specs/**` changed.
9. Outputs via `<file>.tmp` + `mv`; `pr/result.json` is moved last. Commits are logged to
   `pr/commits.tsv` (`kind<TAB>sha<TAB>subject`, kinds `C1 C2 MERGE_MAIN MERGE_BOT AUTOFIX HS`).
10. **Long commands.** Every `make` and `cargo build|check|clippy|test|run` runs detached as `long <prefix> <cmd…>`
    and is joined with `waitx <prefix>` in a separate call passing `timeout: 600000`, under the detached-job
    contract of `grace/workflow/2.0_preflight.md` "Phase 9: Background warm builds"; a gate is then logged with `gx`.
    After `waitx` prints `<exit> <duration_s>`, the join call runs the block's remaining lines. `TIMEOUT:<prefix>` →
    a failed gate. Only `cargo +nightly fmt` runs inline.
11. **Terminal paths.** Once `pr/commits.tsv` has a `C1` row, every return except a Phase 0 `ABORT_GIT_STATE` runs
    Phase 10 Cleanup first.
12. **The manifest is checked in three directions, not two.** Staged-set vs manifest (both ways, Phase 4b via
    `2.4_pr.md` "Step 3") plus manifest vs the deny-list (Phase 2, before any `git add`) — a forbidden path present
    on *both* sides passes the first two. `ABORT_FORBIDDEN_PATH` is not overridable and `git add -f` is not a way
    around it.

## Phase 0: Load and guard

```bash
[ "$(git branch --show-current)" = "$BRANCH" ] || echo GIT_STATE_VIOLATION:branch
[ "$(git stash list | wc -l)" -eq "$(jq -r .stash_count "$P")" ] || echo GIT_STATE_VIOLATION:stash   # 2.0 Phase 7 baseline
git rev-list --first-parent "$BASE_SHA"..HEAD | grep -vxF -f <(cut -f2 "$R/pr/commits.tsv" 2>/dev/null) \
  | head -1 | sed 's/^/GIT_STATE_VIOLATION:foreign_commit /'
git for-each-ref --format='%(refname)' "refs/grace/$RUN_ID/" > "$R/pr/snapshots.txt"
```

Any `GIT_STATE_VIOLATION` → `STATUS: ABORT_GIT_STATE`. HEAD ≠ `BASE_SHA` with every first-parent commit in
`pr/commits.tsv` is a **resume**: skip every phase whose effect is recorded (`commits.tsv`, `pr/pr.json`).

## Phase 1: Status → `pr/status.json`

Per unit (a `plan/plan.json .order[]` entry whose `unit` is in `run.json .units`, in that sequence; `__hs__` is reported
only through `HS_PR` and `HS_CHANGES_REQUIRED`), from `test/final.json .units[<unit>]` (schema:
`grace/workflow/2.6d_test_exec.md` section "Phase 7: Summaries"):
`GRPC_STATUS` = `.grpc_status` (`PASS|FAIL|BLOCKED|NOT_RUN`), `E2E_STATUS` = `.e2e_status`, `OPEN_BUGS` =
`.open_bugs`, `EVIDENCE` = `.evidence.three_hop + .evidence.grpc`. `HS_CHANGES_REQUIRED` = ids of
non-withdrawn `plan.json .hs_changes[]` whose `flows_unblocked` include the unit, else `none`. A unit with no
`final.json` entry: `NOT_RUN` / `E2E_SKIPPED` (reason `not tested`).

**Blocking-unfixed bugs** (the S7 prelude, when it ran, has already moved every non-terminal bug to `unresolved`, so
never match on `status == "open"`). Bugs whose every marker belongs to a withdrawn unit are scope, not a merge
blocker — the code that produced them is no longer in the diff; they still render in "Withdrawn / unresolved":

```bash
W=$(jq -c '[.order[] | select(.status == "withdrawn") | .unit] as $w
     | [.units[] | select(.unit | IN($w[])) | .markers[]]' "$R/plan/plan.json" 2>/dev/null || echo '[]')
{ jq --argjson w "$W" '[.bugs[] | select(.blocking and .in_scope and .duplicate_of == null
     and (.status | IN("fixed","invalid","wont_fix","flaky") | not)
     and ((.flows // []) as $f | $f == [] or (($f - $w) | length > 0)))]' "$R/test/bugs.json" 2>/dev/null || echo '[]'; } > "$R/pr/blocking_bugs.json"
```

A unit's blocking bugs = entries whose `flows[]` intersect its `plan.json .units[].markers[]`.

`FLOW_STATUS`, first match wins:

| FLOW_STATUS | Rule |
|---|---|
| `WITHDRAWN` | `plan.json .order[]` status `withdrawn`, `blocked` or `spec_gap` (never implemented; reason = `order[].reason`), or its latest `code/*-<unit_fs>.json` has `impl_type: withdraw` |
| `no_op` (not a FLOW_STATUS) | `plan.json .order[]` status `no_op`: listed in Summary with `order[].reason`; excluded from the title, `N_DELIVERED`, `N_UNITS` and `specComplianceScore` |
| `UNRESOLVED` | the unit has a blocking-unfixed bug, or `.blocking_open_bugs` non-empty, or `E2E_STATUS=FAILED`, or `GRPC_STATUS` ∈ `FAIL`/`NOT_RUN` |
| `DELIVERED_VERIFIED` | `E2E_STATUS=SUCCESS` |
| `DELIVERED_E2E_BLOCKED` | `E2E_STATUS=E2E_BLOCKED`, **or** `GRPC_STATUS=BLOCKED` and `E2E_STATUS` ≠ `SUCCESS` (nothing passed on any surface; `e2e_reason` names the capability) |
| `DELIVERED_E2E_SKIPPED` | `E2E_STATUS=E2E_SKIPPED` |

`PR_STATUS`, first match wins (re-evaluated after Phases 3, 5 and 8):

| PR_STATUS | Rule | Draft | Labels | Title |
|---|---|---|---|---|
| `FAILED` | no `DELIVERED_*` unit, or empty manifest | yes | `GRACE-auto` `deja-art` `do not merge` | 2.4 FAILED title |
| `INCOMPLETE` | any `UNRESOLVED`; `pr/blocking_bugs.json` non-empty (any unit, review and baseline bugs included); `review/findings.json` absent, or it has a `status: "open"` S0/S1 finding whose `id` is not the `review_ref` of a `test/bugs.json` bug in `fixed\|invalid\|wont_fix\|flaky` (the `INGEST: review` exec may have been skipped — `2_connector.md` "S7 prelude"); `TEST_ENV_FAILED`, `SECRET_LEAK` or `TREE_MODIFIED` in `run.json .flags[]` (the flag name goes in `reasons[]`); `HS_PR` starts with `NOT_RAISED:` while `[.hs_changes[]? \| select(.withdrawn != true)]` is non-empty (HS cannot reach the delivered flows, and this file already calls that `blocking`); a mandatory gate exit ≠ 0; non-mechanical base-drift conflict; `merge-tree unsupported` (Phases 5, 8) | **no** — drafts skip CI | `GRACE-auto` `deja-art` `do not merge` | suffix ` [GRACE-INCOMPLETE]` |
| `PARTIAL` | ≥1 `WITHDRAWN`, the rest delivered or `no_op`, `pr/blocking_bugs.json` empty | no | `GRACE-auto` `deja-art` | plain |
| `READY` | all non-`no_op` units delivered, gates 0, `pr/blocking_bugs.json` empty | no | `GRACE-auto` `deja-art` | plain |

`deja-art` goes on every PR: `.github/workflows/pr-convention-checks.yml` job `deja_art_label_check` fails without it.

`GRACE-auto` goes on every PR GRACE raises, **in both repos** — it is the marker that says a human did not
write this PR, so reviewers and queries can separate automated work from hand-written work. It replaces the
older `GRACE` label; PRs already carrying `GRACE` keep it, and nothing re-labels them.

`specComplianceScore` = mean over all non-`no_op` units of VERIFIED 1.0 / E2E_BLOCKED 0.8 / E2E_SKIPPED 0.6 / else 0,
except **0** for a unit that passed nothing anywhere — `E2E_STATUS` ≠ `SUCCESS` and `GRPC_STATUS` ∈
{`BLOCKED`, `FAIL`, `NOT_RUN`} — so an unverified flow can never sit the PR on the 0.6 gate;
INCOMPLETE → `min(score, 0.5)`; FAILED → 0; two decimals.

`pr/status.json` = `{pr_status, reasons[], score, units:[{unit, flow_status, grpc, e2e, e2e_reason, hs_changes_required[], open_bugs[], evidence[]}]}`.

## Phase 2: Manifest

```bash
cut -f1 "$R/claimed.tsv" | grep -v '^hs:' | sort -u > "$R/pr/claimed_ucs.txt"
git status --porcelain=v1 --untracked-files=all | cut -c4- | sed 's/.* -> //' | sort -u > "$R/pr/dirty.txt"
jq -r '.ucs.untracked_in_scope // [] | .[]' "$P" | sort -u > "$R/pr/preexisting.txt"   # 2.0 Phase 3: pre-date the run
grep -E '^(crates|config)/' "$R/pr/dirty.txt" | comm -23 - "$R/pr/claimed_ucs.txt" \
  | comm -23 - "$R/pr/preexisting.txt" > "$R/pr/unclaimed.txt"
comm -12 "$R/pr/dirty.txt" "$R/pr/claimed_ucs.txt" \
  | grep -E '^(crates/|config/|data/integration-source-links\.json$|\.typos\.toml$)' | grep -v '_generated_' > "$R/pr/c1.txt"
grep -E "^(data/field_probe/($C|$CA)\.json|docs-generated/connectors/($C|$CA)\.md|docs-generated/[^/]+|examples/($C|$CA)/.*)\$" \
  "$R/pr/dirty.txt" > "$R/pr/c2.txt"
grep -q '\.proto$' "$R/pr/c1.txt" && grep -E '^sdk/|_generated_' "$R/pr/dirty.txt" >> "$R/pr/c2.txt"
sort -u -o "$R/pr/c2.txt" "$R/pr/c2.txt"
```

- `unclaimed.txt` non-empty → `STATUS: ABORT_UNCLAIMED_DIRT`, paths in `REASON`.
- `preexisting.txt` paths (untracked before the run, `preflight.json .ucs.untracked_in_scope`) that are not
  claimed are never staged; one decision row listing them.
- **C1** (code) = `c1.txt`. **C2** (generated) = `c2.txt` — the set `2.3b_codegen_unit.md` "Phase 7: `UNIT=__finalize__`"
  claims ("Claim generated output"); with a
  `.proto` change that includes the proto-generated `_generated_` outputs (`git ls-files | grep _generated_`: under
  `crates/ffi/ffi/src/{bindings,handlers}/` and `sdk/{javascript,python,rust}/`), which C1 never holds.
  This overrides `2.4_pr.md` "1c: Stage and commit" ("Do NOT stage these"): the run's own generated output belongs
  in the run's own diff, so a reviewer sees what this connector produced and `git bisect` sees a consistent tree.
  It does **not** make CI's auto-fix a no-op — it fires anyway, over the whole repo, and appends other connectors'
  generated files to this PR. See Phase 9 "Known external defect — CI auto-fix appends other connectors'
  generated files"; do not widen C2 in the hope of pre-empting it.
- Dirty paths in neither set (other connectors' docs, `.omo/`, `grace/**`) are never staged; one decision row.

**Manifest deny-list** — the third direction of the staging verification. Phase 4b's `2.4_pr.md` "Step 3" checks
compare the *staged set* against the manifest in both directions; neither compares the **manifest** against the
prohibitions this file and `2.4_pr.md` "1c" spell out in prose, so a forbidden path present on *both* sides passes
every check (`2.4_pr.md` "Step 1a" is the same check on the single-flow path). It has: one run staged 19 scraped documentation sources under
`grace/rulesbook/codegen/references/<connector>/` plus `grace/scripts/task_update.py` with `git add -f` (defeating
`grace/.gitignore:31` `**/references/**`) and had to untrack them in a later commit, and edited two shared
`global_suites/` files that ~10 other connectors share. Run this over the manifest files themselves, **before any
`git add`**, so nothing forbidden is ever staged (same shape as `pr/unclaimed.txt` → `ABORT_UNCLAIMED_DIRT` above):

```bash
DENY='^grace/|^crates/internal/integration-tests/src/global_suites/|^creds\.json$|^\.env|^task[^/]*\.json$'
DENY="$DENY"'|^\.omo/|^target/|^\.ct-worktrees/|^\.claude/worktrees/|\.md$'
cat "$R/pr/c1.txt" "$R/pr/c2.txt" | grep -vE '^docs-generated/' | grep -E "$DENY" | sort -u > "$R/pr/denied.txt"
[ -s "$R/pr/denied.txt" ] && echo ABORT_FORBIDDEN_PATH
```

- `denied.txt` non-empty → `STATUS: ABORT_FORBIDDEN_PATH`, its paths in `REASON`, **nothing staged and nothing
  committed**. Remove the path from `claimed.tsv`'s effect on the manifest (it was claimed in error: write the
  self-fix per Rule 7 naming the stage that claimed it), rebuild Phase 2, re-run. A `global_suites/` path is never
  fixable here: `2.3a_plan.md:365` and `2.3b_codegen_unit.md:556-560` both rule that a connector run may not edit
  `crates/internal/integration-tests/src/global_suites/` — the case belongs in
  `connector_specs/$C/override.json`, and the run must reach `STATUS: FAILED` rather than stage it.
- `^docs-generated/` is the **only** standing `.md` exemption (generated docs are `.md` by design, C2 owns them).
  A `.md` that is genuinely this connector's deliverable is added to the exemption **by name**, never by dropping
  the `\.md$` clause — the same rule as `2.4_pr.md` "Step 3" ("If a `.md` file is genuinely part of this
  connector's deliverable, it must appear by name in the Step 1 manifest").
- `git add -f` is forbidden here and everywhere (RULES 1). `.gitignore` refusing a path is the answer, not an
  obstacle: a path git declines to stage is a path this PR must not contain.

## Phase 3: Gates → `pr/gates.tsv` (`command<TAB>exit<TAB>duration_s<TAB>tree_sha`)

Tree sha — the exact recipe of `grace/workflow/2.3b_codegen_unit.md` "Phase 7: `UNIT=__finalize__` (S4z)":

```bash
export GIT_INDEX_FILE="$R/pr/.tree.index"; git read-tree HEAD
xargs -a "$R/pr/claimed_ucs.txt" git update-index --add --remove --
T=$(git diff --cached --binary HEAD | sha256sum | cut -d' ' -f1); unset GIT_INDEX_FILE; rm -f "$R/pr/.tree.index"
```

`typos` runs over the manifest only (untracked scratch such as `.omo/` or `task*.json` must not fail it; CI sees
committed files only):

```bash
cat "$R/pr/c1.txt" "$R/pr/c2.txt" | while IFS= read -r f; do [ -e "$f" ] && echo "$f"; done > "$R/pr/typos_paths.txt"
g xargs -r -a "$R/pr/typos_paths.txt" typos --config ./.typos.toml --force-exclude --
```

- `jq -e --arg t "$T" '.pass == true and .tree_sha == $t' "$R/gate/ci_parity.json"` → **reuse**: copy its
  `steps[]` into the Gates table and run only `g cargo +nightly fmt --all --check` and the `typos` line above.
- Otherwise run the commands of `grace/workflow/2.4_pr.md` section
  "1b-2: Local CI-parity validation (MANDATORY, run before staging)" with its interpretation rules and
  caveats — its whole-tree `typos --config ./.typos.toml` replaced by the line above, and a non-mechanical
  failure sets `PR_STATUS=INCOMPLETE` instead of FAILED — plus steps 3–5 of the 2.3b Phase 7 table (schema
  validators, `buf lint`) when their "runs when" condition holds. `make validate-pre-push-fix` and the `cargo test`
  validators run per Rule 10 (`long "$R/pr/gate-<name>" <cmd>`, `waitx`, `gx`); `typos` and `buf lint` through `g`.
- Paths that became dirty during the gates: claim (Rule 5) only those the Phase 2 C1/C2 patterns select, then re-run
  Phase 2. Other connectors' generated drift stays unclaimed, as in 2.3b Phase 7, so Phase 10 restores it:

```bash

grep -q '\.proto$' "$R/pr/c1.txt" && RE="$RE|^sdk/|_generated_"
git status --porcelain=v1 --untracked-files=all | cut -c4- | sed 's/.* -> //' | sort -u | comm -13 "$R/pr/dirty.txt" - \
  | grep -E "$RE" | sed 's/$/\tS7\t__pr__/' >> "$R/claimed.tsv"
```

## Phase 4: Scrub and commit

**4a — needles.** Write once (the file holds logic only, no secret):

```bash
cat > "$R/pr/needles.sh" <<'EOF'
# Source it; consume ONLY as <(needles). Never redirect needles into a file.
# The creds path 2.0 resolved (it sources .env.connector-tests first); never re-resolve here.
CREDS=$(jq -r '.creds.path // empty' "$P")
needles_ok() {   # fail closed; run before every consumer
  [ -n "$CREDS" ] && [ -r "$CREDS" ] || { echo NEEDLES_FAIL:creds_unreadable; return 1; }
  jq -e --arg c "$C" '[.[$c] // {} | paths(strings)] | length > 0' "$CREDS" >/dev/null \
    && [ "$(needles | grep -c .)" = 0 ] && { echo NEEDLES_FAIL:empty; return 1; }; return 0; }
needles() {
  local v; v=$( { jq -r --arg c "$C" '.[$c] // empty | paths(strings) as $p
      | select(($p|index("_comment")|not) and ($p|index("auth_type")|not)) | getpath($p)' "$CREDS"
    [ -f "$SECRETS_ENV" ] && sed -nE "s/^[A-Za-z_][A-Za-z0-9_]*=['\"]?([^'\"]*)['\"]?\$/\1/p" "$SECRETS_ENV"
  } | grep -vE '^https?://' | awk 'length($0) >= 8' | sort -u )
  [ -n "$v" ] || return 0
  printf '%s\n' "$v"
  # Pipes, never <<< (bash < 5.1 spools here-strings to $TMPDIR)
  printf '%s\n' "$v" | while IFS= read -r a; do printf %s "$a" | base64 -w0; echo
    printf '%s\n' "$v" | while IFS= read -r b; do printf %s "$a:$b" | base64 -w0; echo; done   # Basic-auth forms
  done
}
LEAK_RE='eyJ[A-Za-z0-9_-]{5,}\.[A-Za-z0-9_-]{10,}\.[A-Za-z0-9_-]{10,}|-----BEGIN [A-Z ]*(PRIVATE KEY|CERTIFICATE)-----|\bsk_(test|live)_[A-Za-z0-9]{8,}|\b(pk_)?(snd|dev|prd)_[A-Za-z0-9]{32,}\b'
EOF
```

The JWT part mirrors `JWT_TOKEN_RE` in `crates/internal/integration-tests/src/harness/cred_masking.rs`. The HS
key prefixes are a default: with `{HS_REPO_PATH}` present, run `grep -rnE '"(snd|dev|prd)_?"' {HS_REPO_PATH}/crates/router/src | head`
and adjust `LEAK_RE` to the prefixes found (decision row).

**4b — C1.**

```bash
[ -s "$R/pr/denied.txt" ] && { echo ABORT_FORBIDDEN_PATH; exit 1; }   # Phase 2 deny-list: never stage past it
. "$R/pr/needles.sh"; needles_ok || exit 1; xargs -a "$R/pr/c1.txt" git add --
# `git add --` and nothing else. Never `-f`: it is the one flag that turns an ignore rule into a committed file,
# and the run that shipped 19 ignored `references/**` docs into a connector PR had read RULES 1 and done it anyway.
# Never `-A`, `.`, or a directory argument either (RULES 1) — the manifest is the only input to staging.
# 2.4_pr.md "Step 3 — VERIFY the staged set against the manifest, and fail loudly on mismatch" (a) and (b) verbatim (they exit 1), then:
git diff --cached --name-only | grep -E '^(grace/|\.omo/|target/|\.ct-worktrees/|\.claude/worktrees/)' && { echo REJECT; exit 1; }
diff <(git diff --cached --name-only | sort) "$R/pr/c1.txt" > /dev/null || { echo MANIFEST_MISMATCH; exit 1; }
[ "$(git diff --cached | grep -cF -f <(needles))" = 0 ] && [ "$(git diff --cached | grep -cE "$LEAK_RE")" = 0 ] || { echo LEAK; exit 1; }
git commit -m "$SUBJECT" -m "GRACE run $RUN_ID" && printf 'C1\t%s\t%s\n' "$(git rev-parse HEAD)" "$SUBJECT" >> "$R/pr/commits.tsv"
```

`SUBJECT` = the Phase 7 title without ` [GRACE-INCOMPLETE]`. Nothing is committed unless every check passes;
after any fix, re-run the whole block. `NEEDLES_FAIL:*` → Rule 4. `LEAK`: locate the hit with
`git diff --cached --name-only | xargs grep -nF -f <(needles) | cut -d: -f1,2`; remove the value from the
working tree (runtime credential access, as other connectors do) and re-stage. Rejects and mismatches
follow 2.4 Step 3's correction procedure; still mismatched after two rounds → `STATUS: FAILED`,
`REASON: staging manifest mismatch: <paths>`, nothing committed.

**4c — C2** (skip when `c2.txt` is empty): the same block over `c2.txt`, with the 2.4 (a) path reject run as
`git diff --cached --name-only | grep -v '^docs-generated/' | grep -E '<2.4 (a) pattern>'` (generated docs are
`.md` by design). Subject `chore(connector): [$CD] update generated files`; record `C2`.

## Phase 5: Base drift and range scrub

```bash
git fetch origin main
OUT=$(git merge-tree --write-tree --no-messages --name-only origin/main HEAD); MT=$?
tail -n +2 <<<"$OUT" > "$R/pr/conflicts.txt"
```

## Phase 8: Hyperswitch PR

`claimed.tsv` alone never decides "none required": `__hs__` is skipped when `hs_mode ≠ worktree` and may time out
or fail before its first claim. `plan.json .hs_changes` = `null` means **not assessed** (no HS checkout, `2.3a_plan.md`
"Phase 10"), not "none needed" — and neither does `[]`, unless the unit ran (table below). The body renders the two
distinctly, because they are different claims. An item whose `flows_unblocked` are all withdrawn
units carries `withdrawn: true` (`2.3a_plan.md` "Phase 12: AMEND" step 3), so a withdraw can take `HSC` to `[]`; any
`hs-wt` commit already made for it is then simply never pushed.

```bash
HSC=$(jq -c '[.hs_changes[]? | select(.withdrawn != true)]' "$R/plan/plan.json")
MODE=$(jq -r .hs_mode "$R/run.json")
PUSHOK=$(jq -r '.hs.push' "$P")   # 2.0_preflight.md "Phase 4: Hyperswitch checkout (read-only)": false = no write access
ROW=$(jq -r '[.rows[] | select(.id | test("^S4:[0-9]+:__hs__$"))] | last
  | if . then "\(.status):\(.result // "none")" else "none" end' "$R/run.json")
grep -qE ' JOIN [^ ]*__hs__[^ ]* timeout' "$R/events.log" && ROW="$ROW:join_timeout"
grep -qE ' SKIP S4:[0-9]+:__hs__ reason=unit:' "$R/events.log" && ROW="skipped:$(sed -nE 's/.* SKIP S4:[0-9]+:__hs__ reason=(unit:[^ ]*).*/\1/p' "$R/events.log" | tail -1)"
HSPR=<the value the table below selects>      # the ONLY writer of this variable
printf '%s\n' "$HSPR" > "$R/pr/hs_pr.txt.tmp"; mv "$R/pr/hs_pr.txt.tmp" "$R/pr/hs_pr.txt"
```

**`HS_PR` derives from whether the `__hs__` unit actually ran and reached a verdict** — never from `HSC` alone, and
never from the absence of an HS PR. The two values that look interchangeable are not: `none required` is a **claim
the run makes** ("the HS unit ran and found nothing required"), `not assessed` is the absence of a claim. Rendering
a unit that never ran as `none required` asserts an assessment the run did not make; it has shipped (one PR said
`none required` in the machine block while its own prose said "Requires Hyperswitch PR …/14244", and another said it
with its `__hs__` unit skipped for having no items). First match wins:

| # | `__hs__` run state (the evidence that decides it) | `HS_PR` |
|---|---|---|
| 1 | `plan.json .hs_changes` is `null` — no HS checkout, so nothing was ruled in or out (`hs/scout.json` absent or `.hs_available` false; `2.3a_plan.md` "Phase 10") | `not assessed` |
| 2 | `ROW` = `none`, or starts `skipped:` — the unit was never spawned (`2_connector.md` "S4": `ev SKIP S4:<NN>:__hs__ reason=unit:<plan status>` for a `no_op`/`blocked`/`spec_gap`/`withdrawn` order entry, `reason=unit:hs_mode=<mode>`, or `reason=unit:no_items`). **Whatever `HSC` is.** A unit that never ran produced no verdict, including when `plan.json .hs_changes` is `[]` because the scout found `hs_changes_required: []` — that finding renders as prose under "Hyperswitch dependency", it is never promoted to a verdict | `not assessed` |
| 3 | `ROW` starts `failed:`, or carries `:join_timeout`, or is any `done:*` other than `done:DONE`/`done:NO_CHANGE` — **and** `HSC` = `[]`: the unit ran but died before a verdict | `not assessed` |
| 4 | the same states as row 3 with `HSC` non-empty, or `PUSHOK` = `false`, or no `hs:` path in `claimed.tsv` | `NOT_RAISED:<reason>` per the bullet below |
| 5 | `ROW` ∈ {`done:DONE`, `done:NO_CHANGE`} with no `:join_timeout`, **and** `HSC` = `[]` (nothing required, or every item withdrawn after the unit ran — `2.3a_plan.md` "Phase 12: AMEND" step 3) | `none required` |
| 6 | `ROW` ∈ {`done:DONE`, `done:NO_CHANGE`}, `HSC` non-empty, `PUSHOK` = `true`, ≥1 `hs:` path claimed | steps 1–7 below → `<url>`, `pre-existing:<url>` or `NOT_RAISED:<reason>` |

Rows 1–5 need no worktree, so run the block above and the table at the **start of Phase 6**, write `pr/hs_pr.txt`,
and render from it; Phase 8 replaces the value only when row 6 selects it. One decision row records the row number,
`ROW`, `HSC` length and `plan.json .hs_changes` null-ness — the four facts that produced the value.

- Rows 1, 2, 3 and 5 → step 8 (no HS PR is built).
- Row 4 — `HSC` non-empty and (`PUSHOK` = `false`, or no `hs:` path in `claimed.tsv`, or `ROW` starts with neither `done:DONE`
  nor `done:NO_CHANGE`: a timed-out join leaves the row `failed`) → `HS_PR=NOT_RAISED:no_push_access` when
  `PUSHOK` = `false` (there is no point building a branch that cannot be pushed, and RULES 6 forbids retrying the
  failed push), else `NOT_RAISED:hs_mode=$MODE` when `MODE ≠ worktree`, else
  `NOT_RAISED:hs_row=$ROW` (`blocking` comment, Templates). No usable worktree, so step 5 runs on titles and files only
  (a candidate is never `pre-existing:` without the step 5 tree check): open `$HSR` PRs from
  `gh pr list --repo "$HSR" --state open --search "$CD in:title"` whose touched files (`gh pr view <n> --json files`)

## Phase 9: CI auto-fix and final edit

Wait for job `Auto-fix (format + docs + generate)` (`.github/workflows/ci.yml` job `auto-fix`) on
`pr.json .ucs.head_sha` with **one** background Bash waiter (`run_in_background: true`) bounded by
`run.json .caps.ci_autofix_wait_min` (`grace/workflow/2_connector.md` "## Caps" row "CI auto-fix wait (2.8)"). Its loop costs no turns: make
no tool call until it exits, then act once.

```bash
SHA=$(jq -r .ucs.head_sha "$R/pr/pr.json"); MIN=$(jq -r .caps.ci_autofix_wait_min "$R/run.json")
timeout "${MIN}m" bash -c 'until
    ID=$(gh run list --repo juspay/hyperswitch-prism --workflow ci.yml --commit "$0" --event pull_request --json databaseId --jq ".[0].databaseId // empty")
    [ -n "$ID" ] && gh run view "$ID" --repo juspay/hyperswitch-prism --json jobs \
      --jq ".jobs[] | select(.name==\"Auto-fix (format + docs + generate)\") | .status" | grep -qx completed
  do sleep 60; done; echo "ID=$ID"' "$SHA"; echo "AUTOFIX_WAIT exit=$?"   # 124 = not observed within cap
```

On exit 0, read the job's conclusion once: `gh run view <ID> --repo "$UCS" --json jobs --jq '.jobs[] | select(.name=="Auto-fix (format + docs + generate)") | "\(.status) \(.conclusion)"'`.

Then `git fetch origin "$BRANCH"`: new commits all by `hyperswitch-bot[bot]` → `git merge --ff-only FETCH_HEAD`,
record `AUTOFIX`; none → `no-op`; skipped / not seen → recorded verbatim. **Never push again.**

### Known external defect — CI auto-fix appends other connectors' generated files

**Expect this; do not treat it as this run's dirt, and do not try to undo it.** Committing the run's own generated
output (Phase 2, C2) does **not** make the `auto-fix` job a no-op, and Phase 2 must not claim it does. The job
regenerates the **whole repository** regardless of what the PR touched — `.github/workflows/ci.yml:531-533` runs the
`field-probe` binary over every connector and then `make docs SKIP_PROBE=1` — and stages the result with
**`git add -A`** (`ci.yml:541`), commits it as `hyperswitch-bot[bot]` (`ci.yml:537-550`), pushes (`ci.yml:559`) and
sets `pushed=true`, which skips the remaining gate jobs (`ci.yml:599`, `:655`, `:918`) so a fresh run has to start on
the bot commit. So every stale generated file anywhere in the repo lands on whichever PR happens to be open next.

Measured over the 10 `GRACE-auto` PRs: it fired on 5 and added **only** generated files — 189 files on one (119
`data/field_probe/*.json` belonging to unrelated connectors, 56 `examples/`, 15 `docs-generated/`), 32 files over 7
separate bot commits on another, then 18/3, 8/1, 7/1. Each bot commit costs a full extra CI round. Control: 1 of 8
recent non-GRACE merged PRs saw the same thing, so it is not specific to GRACE PRs — GRACE runs just meet it more
often because they change generated inputs.

**This is not a GRACE staging bug and is never written up as one.** On the 189-file PR, GRACE's own commit staged
exactly the 7 files it should have (the connector's own `data/field_probe/<c>.json`, its 4 `examples/<c>/**` files
and 2 `docs-generated/` files) — precisely the set `2.3b_codegen_unit.md` "Phase 7: `UNIT=__finalize__`" ("Claim
generated output") prescribes. The cause is CI's `git add -A` over a whole-repo regeneration. **We are deliberately
not changing `.github/workflows/ci.yml` in this pipeline**; the cause is recorded here and left there.

Consequences for this phase, all mandatory:

- Bot commits touching paths in neither C1 nor C2, including other connectors' `data/field_probe/*.json`,
  `docs-generated/**` and `examples/**`, are **expected**. `git merge --ff-only FETCH_HEAD` them in as above and
  record `AUTOFIX`. Never `git revert`, never `git restore` them, never re-push a cleaned branch (RULES 1 allows one
  push per repo per invocation and this phase has spent it).
- Do not count them as `unclaimed.txt` dirt, a `TREE_MODIFIED` flag or a reason for `INCOMPLETE`: they were never in
  this run's working tree. The Output "Final guard" reads HEAD against `commits.tsv`, and the `AUTOFIX` row is what
  makes the bot's sha legitimate there.
- Several bot commits in a row are normal (7 on one PR): each fresh CI run can regenerate more. Merge whatever
  `FETCH_HEAD` holds in one `--ff-only`; do not loop waiting for quiescence, and do not re-arm the waiter.
- Render the count honestly under Commits — `CI auto-fix: <sha> fast-forwarded (<n> files, <m> commits; includes
  other connectors' generated files — see ci.yml `auto-fix`)` — so a reviewer reading a 189-file diff knows which
  files the run authored and which CI appended.

Label check: `gh run list --repo "$UCS" --workflow pr-convention-checks.yml --commit "$SHA" --json databaseId,conclusion`;
job `Verify PR carries the deja-art label` failed (labels land after `opened`; `labeled` is not a trigger) →
`gh run rerun <id> --failed --repo "$UCS"`.

Final: re-render (Commits, HS link, comment URLs), 6d–6e, `gh pr edit --body-file`, PATCH every overflow comment
with `gh api -X PATCH repos/juspay/hyperswitch-prism/issues/comments/<id> -F body=@<file>` (one no longer
needed keeps its tag line plus `(content moved back into the PR description)`; never deleted). Verify
`diff <(gh pr view <N> --repo "$UCS" --json body -q .body | sed 's/[[:space:]]*$//') <(sed 's/[[:space:]]*$//' "$R/pr/body.md")` is empty.
