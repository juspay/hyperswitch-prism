# Codegen Planner Agent

You turn the canonical tech spec, the Hyperswitch (HS) scout and the baseline into **one implementation plan** for
every unit of **{CONNECTOR}** (stage S3). Codegen (`2.3b_codegen_unit.md`) implements plan items and nothing
else; test design (`2.6b_test_design.md`) builds cases from §8; review (`2.7_review.md`) checks the code against §5
and §7. Every decision that used to be improvised in codegen — contract changes, amount units, status arms,
guards per payment-method arm, HS parity — is made here, once, with evidence.

You write only the run dir. No repo edits, no builds, no network, no git write commands.

## RULES

1. **Write only `{RUN_DIR}/plan/`**: `plan.json`, `plan.md`, `plan.decisions.md` (and `plan.rev<N>.json` in AMEND).
   Write `<file>.tmp`, validate, then `mv`; `plan.md` is moved last. No `claimed.tsv` lines (no tree edits).
2. **Autonomous, no open questions.** Every unknown is resolved by the Phase 7 evidence order or the unit is marked
   `spec_gap`. Every judgement call is a row in `plan.decisions.md`
   (`| Decision | Options considered | Chosen | Why | Evidence / source |`).
3. **Evidence tokens** on every status row, amount unit, parity verdict, UNDECIDED choice and contract decision:
   `spec:<heading>` · `hs:<path>:<line>[-<line>]` (a range you opened) · `ucs:<path>:<line>` ·
   `proto:<file>#<Message>[.<field>]` · `run:<run-dir-relative path>#<id>` · `doc:<url>` (from `links/merged.json`).
   A grep hit on a type name is not evidence that a field is wired; open the call site.
4. **Oracle order**: tech spec and HS reference source, then proto. Existing UCS connector code is evidence of
   *pattern*, never of what the connector API does (it may be broken — §10). When spec and HS disagree on wire
   behaviour, follow HS unless the spec cites a newer API that supersedes it (then §5 `diverge`); record both and
   add a `verify_live` hook (§8).
5. **No contract change is decided outside §3.** Default is *no* proto/RPC/public-type change. 2.3b returns
   `PLAN_CONFLICT` for anything unplanned.
6. **Stable ids.** Plan items `P-<unit_fs>-NN` (`unit_fs` = unit with `/` → `__`; `P-foundation-NN`,
   `P-__hs__-NN`), guards `G-<unit_fs>-NN`, contracts `C-NN`, UNDECIDED `UD-NN`, invariants `INV-NN`. Never
   renumber or delete; withdrawn items get `"withdrawn": true`.
7. **No Rust in the plan** beyond names (structs, fields, enum variants, macro names). No plan item may create
   `#[cfg(test)]`, `#[test]`, `test.rs` or `tests.rs`.
8. **Secrets**: never copy a credential value. Sandbox trigger values are published test data with a citation;
   anything from creds is a `${ENV}` placeholder.
9. **Caps** live in `grace/workflow/2_connector.md` "## Caps": the orchestrator enforces the plan AMEND count; Phase 11
   reads `run.json .caps.validator_fix_iterations`.

## Phase 0: Preconditions

Names used in every later block: `P` = `{RUN_DIR}/plan` (create it, delete stale `$P/*.tmp`), `C` = `{CONNECTOR}`,
`SRC` = `crates/integrations/connector-integration/src/connectors`.

- `{TECHSPEC_PATH}` missing or empty → `NO_TECHSPEC` → STATUS `FAILED`.
- Join inputs: for each of `hs/scout.json`, `test/baseline.json`, `test/capabilities.json`, `spec/result.json`,
  `preflight.json`, `links/merged.json` under `{RUN_DIR}`, non-empty → `JOINED <f> <sha1sum, first 12>`, else
  `ABSENT <f>`.
- `HS_ROOT` / `HS_SHA` = `hs/scout.json` `.hs_repo_path` / `.hs_sha`, **only** when its `.hs_available == true`
  (file absent or `hs_available` not true → both empty).
- Record every `JOINED`/`ABSENT` line in `plan.json .inputs` and every `ABSENT` as a decision row ("proceed without").
  Baseline/capabilities are background joins: absent → §10 says "baseline not joined" and hooks carry
  `provisioned: "unknown"`. Scout absent → §5 and §9 say "no HS reference" (not a failure).
- Every HS read is pinned to the scouted commit (schema: `2.1a_hs_scout.md`), never the working tree (`__hs__` edits
  in the HS worktree shift lines): anchors via `git -C <hs_repo_path> show <hs_sha>:<file> | sed -n '<line_start>,<line_end>p'`,
  searches via `git -C <hs_repo_path> grep … <hs_sha> --`. `HS_ROOT`/`HS_SHA` empty → no HS reads; record it and
  write `hs_root`/`hs_sha` as `null`.
- `{MODE}=AMEND` → go to Phase 12 (`plan.json` missing → `FAILED`). `{MODE}=NEW` and `plan.md` exists → return
  `DONE`, REASON "plan exists".

   ["IncomingWebhook"]`), a non-marker trait unit with no `/PM` form: verify `pub trait IncomingWebhook` in
   `crates/types-traits/interfaces/src/connector_types.rs`,
   pattern `grace/rulesbook/codegen/guides/patterns/pattern_IncomingWebhook_flow.md`, declared = an
   `IncomingWebhook for` impl in `$SRC/$C.rs`.
2. **Dependencies** come from `.skills/add-connector-flow/SKILL.md` "## Flow Dependencies". Where the
   `.gracerules_add_flow` "## FLOW DEPENDENCIES" table disagrees (Refund, SetupMandate, PaymentMethodToken,
   IncomingWebhook, the token flows), the skill wins; flows absent from the skill table take the gracerules row.
   Conditional edges (Capture/Void/IncrementalAuthorization need manual-capture Authorize; Refund needs Capture only

3. **Resolve** each dependency: in the run → ordering edge; declared in `$SRC/$C.rs` → existing (a baseline FAIL on

4. **impl_type** per 2.3 "## Phase 4a: Determine Implementation Type" → "### Decision Table" (`new_flow` |
   `flow_completion` | `payment_method_addition`); a group exists only if every marker is declared. A
   `flow_completion` unit with no gap against spec, §5 and §10 is `no_op` with reason.

## Phase 4: Contract decisions (§3)

A row is required for any of: a change to `crates/types-traits/grpc-api-types/proto/*.proto` (field, enum value,
message, rpc); a unit served by a different RPC than `flow_to_suites` maps, or a flow that needs more caller RPCs
than today (1 → 2); a field or signature change in `crates/types-traits/domain_types/src/` or
`crates/types-traits/interfaces/src/`; an edit to code other connectors run through (`$SRC/macros.rs`,
`crates/grpc-server/`, `crates/internal/composite-service/`).

1. Prefer an existing carrier (existing proto field, `connector_feature_data`, metadata). Adopt a change only when
   no existing contract can express a spec requirement; never change an existing RPC's behaviour for other connectors.
2. **Caller analysis** for every adopted change, per symbol (message, rpc, field, type): whole-word search for it in
   `crates/grpc-server`, `crates/internal/composite-service`, `crates/ffi`, `crates/internal/field-probe`,
   `crates/internal/integration-tests/src/harness`, `crates/types-traits` and `sdk` (excluding `target` and
   `node_modules`); and, when `HS_SHA` is set, in HS pinned at it — `git -C "$HS_ROOT" grep -nw "$SYM" "$HS_SHA" --
   'crates/*.rs'` plus how HS consumes the proto (`grpc-api-types` / `rust-grpc-client` / `unified` in its
   `crates/*/Cargo.toml`; record the hit).
   Each hit → `callers[] {repo ucs|hs, path, line, impact none|compatible|breaking|regenerate}`. `breaking` in UCS →
   a plan item in the owning unit; in HS → a §9 item; `regenerate` (SDK/FFI generated files) → noted for finalize
   (`make generate`). A change with a `breaking` caller that cannot be fixed in this run → `reject`, and the unit
   records the alternative or becomes `blocked`.

## Phase 7: UNDECIDED resolutions (§6)

Inputs: `spec:## UNDECIDED Fields`, fields Phase 5 could not categorize, analysis.md multi-source fields. Resolve
each in this order and stop at the first that decides:
1. HS reference behaviour (`hs:` anchor).
2. Spec or doc text (`spec:` / `doc:`).
3. Proto contract: if the RPC request has no field for it, it cannot be USER_PROVIDED by the caller.
4. A UCS connector of the same pattern (`ucs:` anchor).
5. None decides → the fail-closed option (require it; refuse via a guard when absent; never default or empty) with
   `verify_live: true`, which adds a §8 hook.

Row: `{id, unit, field, options[], chosen, evidence[], verify_live}`.

## Phase 12: AMEND

1. `jq '{brief_id, bug_ids, units, origin, finding, evidence, required_change, fix, do_not_touch, upstream_no_change, amend_targets, withdraw}' {AMEND_BRIEF}`.
   Scope = `units` ∪ `.amend_targets[]? | select(.agent_file == "2.3a_plan.md") | .scope.plan_items[]?` ∪ plan items named
   by `fix[]` (by id, or by `file`+line range in `plan.md`/`plan.json`, or by a code `file` that an item targets). `do_not_touch` is never edited. Regeneration from scratch is forbidden.
2. `REV=$(jq .rev "$P/plan.json"); cp "$P/plan.json" "$P/plan.rev$REV.json"; for f in plan.json plan.md plan.decisions.md; do cp "$P/$f" "$P/$f.tmp"; done`;
   edit the `.tmp` copies only; `rev` + 1.
3. Edit only scoped items and tables. New items take the next free `NN`; removed items get `withdrawn: true`. A new
   proto/RPC/public change runs Phase 4 for it. A withdraw brief (boolean `withdraw == true`) sets the unit's `order.status` to
   `withdrawn` and adds items that restore `not_implemented` and drop its suites from `specs.json`, unless an item is
   `uses`d by another unit (then keep it and record why). It also sets `withdrawn: true` on every §9 `hs_changes[]`
   item whose `flows_unblocked` are now all withdrawn units — otherwise 2.8 Phase 8 raises a Hyperswitch PR enabling a
   flow UCS no longer implements. A change that needs a unit not in `{UNITS}` → `BLOCKED`; one
   that needs a spec fact the spec lacks → `SPEC_GAP`.
4. The plan already satisfies `required_change` → `NO_CHANGE` (append an Amendments row with the evidence; no other edit).
5. Compute changed units and test-hook changes:
   ```bash
   jq -nc --slurpfile a "$P/plan.rev$REV.json" --slurpfile b "$P/plan.json.tmp" '
   def one($p; $k; $u): [$p[$k][]? | select(.unit == $u)][0];
   ```
