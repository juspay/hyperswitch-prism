# Codegen Unit Agent

You implement **one unit** of the approved codegen plan for **{CONNECTOR}**: plan §4[`{UNIT}`], in the UCS
working tree, lint-clean. The same file drives the three special units: `__hs__` (the Hyperswitch changes of
plan §9, in the run's HS worktree), `__promote__` (test-data deltas of passing cases into `connector_specs/`) and
`__finalize__` (stage S4z, the CI-parity gate over the whole tree).

You do not design. The planner (`grace/workflow/2.3a_plan.md`) already fixed order, contracts, HS parity and
invariants; the techspec is the only other source of truth. When either cannot be followed as written you
stop and return an escalation status. You never improvise, never commit, never use the web, and never ask a
question: every judgement call goes into the decisions file.

Setup (all commands from the UCS repo root unless stated):

```bash
RUN=$(realpath {RUN_DIR}); mkdir -p "$RUN/code" "$RUN/gate"
UNIT_FS=$(printf '%s' '{UNIT}' | sed 's#/#__#g')
STAGE=S4; [ '{UNIT}' = __finalize__ ] && STAGE=S4z
OUT=$RUN/code/{NN}-$UNIT_FS.json; [ $STAGE = S4z ] && OUT=$RUN/gate/ci_parity.json
cat > "$RUN/code/.{NN}.env.sh" <<EOF
RUN='$RUN'; UNIT_FS='$UNIT_FS'; STAGE='$STAGE'; OUT='$OUT'; DEC='${OUT%.json}.decisions.md'
BASE_SHA='$(jq -r .base_sha "$RUN/preflight.json")'; RUN_ID='$(jq -r .run_id "$RUN/preflight.json")'
CREDS='$(jq -r '.creds.path // empty' "$RUN/preflight.json")'
DETACHED_WAIT_MIN='$(jq -r '.caps.detached_wait_min // empty' "$RUN/run.json")'
EOF
cat >> "$RUN/code/.{NN}.env.sh" <<'EOF'
claim() { printf '%s\t%s\t%s\n' "$1" "$STAGE" '{UNIT}' >> "$RUN/claimed.tsv"; }   # hs paths: claim "hs:<path>"
# long/waitx: detached-job contract, grace/workflow/2.0_preflight.md "Phase 9: Background warm builds"
long() { local p=$1; shift; rm -f "$p.exit" "$p.pid"
  nohup setsid bash -c 'p=$1; shift; echo $$ >"$p.pid"; s=$(date +%s); "$@" >"$p.log" 2>&1; e=$?
    echo "$e $(( $(date +%s) - s ))" >"$p.exit.tmp" && mv "$p.exit.tmp" "$p.exit"' _ "$p" "$@" </dev/null >/dev/null 2>&1 & }
waitx() { timeout 540 bash -c 'until [ -e "$0" ]; do sleep 15; done' "$1.exit" && { cat "$1.exit"; return; }
  [ $(( $(date +%s) - $(stat -c %Y "$1.pid" 2>/dev/null || echo 0) )) -ge $(( ${DETACHED_WAIT_MIN:?} * 60 )) ] || return 124
  local j; j=$(cat "$1.pid"); case "$(readlink "/proc/$j/exe" 2>/dev/null)" in */bash)
    tr '\0' ' ' <"/proc/$j/cmdline" | grep -qF -- "$1" && kill -TERM -- "-$j";; esac; echo "TIMEOUT:$1"; return 125; }
EOF
```

§1's first unit, the §2 items are part of its scope.

## RULES

1. **Scope is the plan.** NEW implements plan §4[`{UNIT}`] (+ §2 for the first unit); AMEND implements the
   brief. No other connector, no core-flow logic, no refactor, no "while I'm here". 2.3's scoping rule applies:
   `grace/workflow/2.3_codegen.md` section "Rules" item 4.
2. **Claim before write.** Call `claim <path>` before the first edit of every path in this spawn. Allowed paths:
   the allowlist in `grace/workflow/2.3_codegen.md` section "Do NOT write Rust test code" (`crates/**`,
   `config/**`, `data/integration-source-links.json`, `.typos.toml`), plus generated outputs at S4z (Phase 7).
   Never `grace/**`, `*.md`, `task*.json`, `creds.json`, `.env*`.
3. **No Rust test code** (`#[cfg(test)]`, `#[test]`, `test.rs`) — `grace/workflow/2.3_codegen.md` section
   "Do NOT write Rust test code". No `cargo test` except the two schema tests in Phase 7.
4. **No git writes** in either repo: no `add`, `commit`, `push`, `stash`, `reset`, `checkout`, `restore`,
   `clean`. Read-only git (`diff`, `show`, `status`, `blame`) and a private `GIT_INDEX_FILE` under `$RUN` are fine.
5. **No web, no questions.** No WebFetch/WebSearch/curl to docs. No UCS server and no grpcurl outside Phase 5.
6. **Escalate, never improvise** (table below). On escalation: stop editing, do not revert, keep your claims,
   write the output with `gate = {command: null, iterations: 0, last_exit: null}` and return.
7. **Secrets** never reach `$RUN` or the repo. Transcripts use `${ENV}` placeholders; credential values are read
   at call time and held only in shell variables.
8. **Bounded gate.** Iteration caps come only from `grace/workflow/2_connector.md` section "Caps" (row
   "Gate iterations per codegen spawn / finalize"); they replace 2.3's "Maximum 7 total loop iterations".
   The anti-loop rules of `grace/workflow/2.3_codegen.md` section "CRITICAL — Anti-loop safeguards (violation =
   immediate FAILED):" apply verbatim: a code change between runs, a fix log, 3 strikes on an identical error.
9. **Output last.** Write `$DEC`, then `$OUT.tmp`, then `mv "$OUT.tmp" "$OUT"` as the final action.
10. **Shell state and long commands.** Bash state does not persist between calls: every block after Setup starts
    with `. {RUN_DIR}code/.{NN}.env.sh` from the UCS repo root, and a value a later block needs is appended there as
    `KEY='value'` (never a secret). Every `cargo build|check|clippy|test` and `make` command runs as
    `long <prefix> <cmd…>` and is joined with `waitx <prefix>` in a separate call, under the detached-job contract of
    `grace/workflow/2.0_preflight.md` "Phase 9: Background warm builds" (join calls pass `timeout: 600000`;
    `TIMEOUT:<prefix>` → `FAILED`). A wait is not a gate iteration.

| Trigger | STATUS | REASON must name |
|---|---|---|
| A change to a `.proto`, an RPC, or a public type/trait/signature outside `crates/integrations/connector-integration/src/connectors/{connector}*` that plan §3 does not list | `PLAN_CONFLICT` | plan item, `file:line` you would change, why |
| A plan §4 `guards[]` entry (negatives in §8) cannot be applied in every arm of its `arms` (the arm lacks the input, or a shared builder bypasses it) | `PLAN_CONFLICT` | guard, arm, `file:line` |
| A plan item relies on a type, field or macro argument that does not exist in the tree, and no change inside the connector module keeps the item's behaviour | `PLAN_CONFLICT` | item, missing symbol |
| The techspec is silent or contradictory on a value the item needs (endpoint, field, status, amount unit, auth) and plan §6 does not resolve it | `SPEC_GAP` | spec section, the exact question |

## Phase 3: Amend (MODE=AMEND)

`{UNIT}` = `__promote__` → Phase 6a instead. Read `{AMEND_BRIEF}` and the unit's latest prior output
(`ls $RUN/code/*-$UNIT_FS.json | sort | tail -1`); carry its `files_modified` and `plan_item_map` forward.
`{UNIT}` not in the brief's `units` → `FAILED`, REASON "brief not for this unit". `do_not_touch` is absolute.
Regeneration from scratch is forbidden: never delete-and-rewrite a function or file the brief does not name.
`upstream_no_change: true` changes nothing you do; note it in `$DEC`.

**`withdraw == true`** (boolean brief field, set by `2.6e_rca.md` and by the `o-wd-*` and `wd`
briefs of `2_connector.md`) → the withdraw procedure below; `fix[]` and the wording of `required_change` are not consulted.

**`fix[]` non-empty** — for each hunk whose `repo` (`2.6e_rca.md` `fix[].repo`) is this unit's tree (`ucs` for
code units, `hs` for `__hs__`; any other hunk, and any hunk whose `file` is under `grace/` whatever its `repo`, is
skipped and recorded as a deviation — `grace/**` belongs to its own stage, never to codegen):

| Tree state at `file:line_start-line_end` | Action |
|---|---|
| equals `current` | apply `suggested_change` exactly |
| differs, but `current` occurs exactly once in `file` | apply there; deviation `line drift` |
| already equals `suggested_change` | no-op |
| `current` not found or ambiguous | stop: `FAILED`, REASON `brief hunk <i> does not match tree` |

After the hunks, also implement the plan §4[`{UNIT}`] items in `.items` of the newest `plan.json .amendments[]` entry
whose `brief_id` equals the brief's (a 2.3a AMEND on this brief); items the tree already satisfies stay untouched.

A plan item with `withdrawn: true` is **never** implemented — not in the `.items` loop above, not in the reconcile
below, not in Phase 1's NEW read: it was removed by a withdraw
(`2.3a_plan.md` "Phase 12: AMEND" step 3), and re-adding it would resurrect code the run took out while `plan.json
.order[]` and 2.8 still call the unit `WITHDRAWN`. If the tree still contains one, remove it per the withdraw
procedure.

**`fix[]` empty** (`withdraw` false) — `required_change` is the instruction: implement it, limited to plan
§4[`{UNIT}`] (+ §2 when `{UNIT}` is §1's first unit). This is also the resume reconcile: finish the items of that
scope the tree lacks (§2 included for the first unit, even when `required_change` names only §4) and leave lines
that already satisfy an item untouched.

**Withdraw procedure** (return the unit to not implemented, by hand edits — never `git restore`/`checkout`):
1. Find what the run added for the unit: prior `plan_item_map` entries + `git diff $BASE_SHA -- <files_modified>`.
   For every type or function you would remove, `grep -rn '<symbol>' crates/integrations/connector-integration/src/connectors/{connector}*`;
   used by another unit's code → `BLOCKED`, REASON `withdraw: shared code <symbol> used by <unit>`.
2. Remove the unit's markers from `create_all_prerequisites!` and their `macro_connector_implementation!` blocks,
   and add them back to the `not_implemented:` list of this connector's `macro_connector_flow_status_impls!`
   **invocation**, in `crates/integrations/connector-integration/src/connectors/{connector}.rs`. `macros.rs` holds
   only the macro *definition* (its matcher arms mention `not_implemented:` too) and is shared by every connector —
   never edit it. For `Marker/PaymentMethod` remove only
   the payment-method arm and restore the refusal it had at base (`git show $BASE_SHA:<file>`).
3. Remove the unit-only request/response types and `TryFrom` impls; undo registration edits made only for this unit.
4. Remove the unit's suites (per `flow_to_suites`) from `specs.json` `supported_suites`.
5. `impl_type = withdraw`; run Phase 4.

All hunks and amendment items no-op → `NO_CHANGE` (gate not run). Otherwise run Phase 4. In `$DEC`, copy the `## Amendments`
section from the prior decisions file (create it if absent: `| When (UTC) | Who | Brief | What changed |`) and
append `| <utc> | S4 2.3b_codegen_unit {NN} | <brief_id> | <file:line list> |`.

## Phase 4: Gate (replaces 2.3 "Phase 6-7: Build & Test Loop")

No build, no server, no grpcurl. The gate is clippy on the connector crate plus every other workspace package
that owns a path you edited:

```bash
. {RUN_DIR}code/.{NN}.env.sh
cargo metadata --no-deps --format-version 1 \
  | jq -r '.packages[] | .name + "\t" + (.manifest_path | rtrimstr("/Cargo.toml"))'   # name <TAB> abs dir
# PKGS = "-p connector-integration" + "-p <name>" per package dir holding a claimed path; append PKGS='…' to the env file
```

Each iteration (the log is `$RUN/code/{NN}-$UNIT_FS.gate.log`; `waitx` prints `<exit> <duration_s>`):

```bash
. {RUN_DIR}code/.{NN}.env.sh; G=$RUN/code/{NN}-$UNIT_FS.gate
long "$G" cargo clippy $PKGS --all-features -- -D warnings
# join, a new call (RULES 10): the first line, then waitx "$G"
```

Loop until exit 0:
1. Read the first `error`/`warning` block with its `--> file:line` (`grep -nE '^(error|warning)' -A8`).
2. The location is in a path you did not claim and did not cause → do not edit; `FAILED`,
   REASON `gate red outside unit scope: <file:line>`.
3. Fix, then append `{iteration, error (first line), file, change}` to `fix_log` **before** re-running. If you
   cannot fill all four, or the same first error line appears a 3rd time, or the cap is reached → `FAILED`.
4. `Blocking waiting for file lock` is a background warm build: keep calling `waitx`; it is not an iteration.

Green → run the plan §7 invariant check (Phase 2 item 6), then Phase 5 if `{SMOKE}=1`, else Phase 8.

## Phase 5: Foundation smoke (`{SMOKE}=1`, gate green)

One debug build, one server, one call for the unit's primary flow. No source edits in this phase; any failure
→ return `FAILED`, REASON `foundation smoke: <first failing line>`; the orchestrator re-AMENDs this unit with
`SMOKE=1`; at the codegen AMEND cap, S5 round 1 reproduces it and RCA routes it.

```bash

  long "$S.build" cargo build -p grpc-server -p integration-tests --bin grpc-server --bin test_ucs
else echo NO_CREDS; fi   # → FAILED, REASON `foundation smoke: .creds.path null or unreadable`

```

`S` set as above):


  decide which side failed" allow one re-derived re-send.
- **Evidence:** `$S.txt` = the command with `-H 'x-connector-config: ${UCS_CONNECTOR_CONFIG}'` + the full response;
  for `test_ucs`, the command + that row's `{suite, scenario, assertion_result, response_status, error, res_body}`.

| Failing step | Allowed fix | Otherwise |
|---|---|---|
| `typos` in a claimed file | fix the misspelling in our own identifier/comment; a vendor or wire spelling (serde rename, API enum string, URL, spec field name) → add it to `[default.extend-words]` in `.typos.toml` with a `# {connector}: <why>` comment and claim `.typos.toml`.
