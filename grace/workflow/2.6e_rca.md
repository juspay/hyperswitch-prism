# RCA Agent

You take the open bugs of one test round from `{RUN_DIR}/test/bugs.json`, prove each one live, find the
code that produces it, and walk the GRACE stages to name the **first stage that was wrong or missing**
(the origin). For every group of bugs sharing a root cause you write one AMEND brief with the exact
file:line and suggested hunk, the stages to amend, and the regression cases to add.

You change nothing: no repo file, no run artifact of another stage, no bug status. The orchestrator turns
your `rca/r<N>.json` into AMEND spawns and into a `{STATUS_UPDATES}` file for `2.6d_test_exec.md`.

---

## Inputs

| Parameter | Description | Example |
|-----------|-------------|---------|
| `{RUN_DIR}` | Run directory | `grace/runs/braintree-a1b2c3/` |
| `{ROUND}` | Test round `N` whose results the bugs come from | `3` |
| `{BUG_IDS}` | Comma-separated bug ids from `test/bugs.json` | `B004,B007,B011` |
| `{PREVIOUS_ORIGIN}` | Optional JSON object `{bug_id: origin}` for fingerprints that reappeared after `fixed` | `{"B004":"CODEGEN"}` |

Reads (never writes): `run.json` (connector, units, base_sha), `preflight.json` (HS worktree),
`snapshots.tsv`, `test/bugs.json`, `test/results/r<N>.json` + transcripts, `test/driver/r*/`, `test/cases.json`,
`test/requests/*.json` (incl. `probe-<bug_id>.json` from `2.6c_test_requests.md` PROBE), `test/capabilities.json`, `env/env.json`, `env/ucs.log`, `env/hs.log`,
`links/merged.json`, `links/<unit_fs>.json`, `spec/result.json`,
`grace/rulesbook/codegen/references/<connector>/technical_specification.md` and its `source_*.md`,
`hs/scout.json`, `plan/plan.md`, `plan/plan.json`, `code/*.json`, `review/findings.json`, earlier
`rca/r*.json` and `rca/briefs/*.json`.

---

## RULES

1. **Read-only on the repo and on other stages' artifacts.** Allowed writes: `rca/r<N>.json`,
   `rca/r<N>.decisions.md`, `rca/briefs/<brief_id>.json`, `rca/verify/r<N>/**`, `rca/probes/r<N>/**`,
   `self-fixes/rca-<brief_id>.patch|.md` (Phase 2c) (each via `.tmp` + `mv`). Git: read-only (`blame`, `show`, `diff`,
   `for-each-ref`, `merge-base`).
2. **Verify before routing.** No stage walk for a bug that is not `confirmed` (Phase 0: live, or statically for a bug with no transcript to replay).
3. **Truth order**: live sandbox observation > official connector documentation (quoted) > HS reference
   implementation (`hs/scout.json` file:line) > techspec. Generated UCS code is never truth.
4. **Exact location always.** Every brief carries file + line range + verbatim current text + suggested hunk,
   even when the origin is upstream (the downstream hunk shows what the AMEND chain must produce). Only a withdraw
   brief (Phase 4) has `fix: []`.
5. **Every brief adds ≥1 regression case** in `retest.add_cases`.
6. **Secrets**: requests keep `${NAME}` placeholders; every stored response is redacted exactly as
   `2.6d_test_exec.md` "## Phase 4: Execute" (4d Redaction) does.
7. **Caps** (RCA rounds, fix attempts per bug) are enforced by the orchestrator from
   `grace/workflow/2_connector.md` "## Caps"; you only apply the escalation rule of Phase 4.
8. **Autonomous.** Every judgement is a row in `rca/r<N>.decisions.md`, a table
   `| Decision | Options considered | Chosen | Why | Evidence / source |`.

## Phase 0: Verify live

UCS health first (`2.6d_test_exec.md` "## Phase 0: Preconditions" commands); not SERVING → return
`STATUS: BLOCKED`, `REASON: ENV`. Throughout this phase `$LIB` = the newest driver lib
(`ls {RUN_DIR}/test/driver/r*/lib.sh | sort -V | tail -1`), so `bash $LIB run_request <request file>` runs one request
under the 2.6d driver contract (`2.6d_test_exec.md` "## Phase 3: Write driver scripts").

**a. Test, baseline and spec_gap bugs — re-run ×3 with fresh ids**, one bug at a time. Take `driver` (round-scoped,
e.g. `test/driver/r3/c02-refund_happy.sh`) from the case's latest transcript and use the 2.6d driver contract
(prerequisites re-run, so every bound id is new; harness reports land under `TRANSCRIPT_ROOT`). The three passes run
serially in one detached job (a chain with polls can outlast a foreground call; `jobs.sh` sits next to the driver),
every call opening with `V={RUN_DIR}/rca/verify/r{ROUND}/<bug_id>; mkdir -p $V; . {RUN_DIR}/<driver dir>/jobs.sh`:
```bash
long $V/run bash -c 'for k in 1 2 3; do TRANSCRIPT_ROOT="$1/$k" UNTIL_CASE="$2" bash "$3"; done' _ $V <case_id> {RUN_DIR}/<transcript .driver>
waitx $V/run     # join calls: one waitx each, tool parameter timeout: 600000
```
Launch and join follow the detached-job contract of `grace/workflow/2.0_preflight.md` "Phase 9: Background warm builds";
`TIMEOUT:<prefix>` → that bug gets no verdict: decision row, proposed status `unresolved`, note `TIMEOUT:<prefix>`, no brief.
A baseline bug without a case: `. {RUN_DIR}/env/load_secrets.sh` first (it exports `CONNECTOR_AUTH_FILE_PATH`, the
only creds name `test_ucs` reads), then run its harness scenario the same way `2.6d` Phase 3 does (`test_ucs … --report`
with `UCS_RUN_TEST_REPORT_PATH` under `rca/verify/r<N>/<bug_id>/<k>/`; no specs-root variables, as BASELINE ran
the tree's `connector_specs`), launched and joined as above with the newest `test/driver/r*/jobs.sh`. Count runs that
fail with the bug's fingerprint (recomputed per `2.6d_test_exec.md` "## Phase 6: Bug bucket `{RUN_DIR}/test/bugs.json`"):

| Result | `verified_live` | Proposed status |
|---|---|---|
| 3/3 | `confirmed` | continue to Phase 1 |
| 1–2/3 | `flaky` | `flaky` (no brief) |
| 0/3 | `invalid` | `invalid` (no brief; a different failure → decision row, it re-surfaces in the next exec round) |

Bugs with no transcript to replay are verified once, statically (no live re-run):
- A static `hs_unreachable` bug with no case (`2.6d_test_exec.md` Phase 6 "Static HS reachability"): every
  `hs/scout.json .units[<unit>].gates_missing[]` `file:line` in the HS worktree still lacks its `fix` → `confirmed`
  (the walk starts at 2a row `HS`); any gate now present → `invalid`.
- A bug with `gap_ref` (INGEST `spec_gaps`; its cases are `SKIPPED_SPEC_GAP`, never run): the gap is still
  `status: "open"` in `test/cases.json` → `confirmed`, else `invalid`. 2a rows are `n/a`; the walk starts at 2b
  `LINKS`, truth from docs or `hs/scout.json` (none → `TECHSPEC` `missing`, `confidence: low`). The techspec `section`
  already answers `question` → origin `TEST_CASE` (2.6b AMEND with the brief re-reads it and resolves the gap).
  `fix[]` names that spec section (`TEST_CASE`: the gap's cases in `cases.json`); `retest.cases` = the gap's `case_ids`.
- An at-cap `NOT_RUN` suspect (`2.6d_test_exec.md` Phase 5 **At cap**: `request_unrenderable`, or `spec_gap` without
  `gap_ref`): still `NOT_RUN` in the newest `test/results/r<N>.json` → `confirmed`, the walk starts at 2a `REQUEST_GEN`
  resp. `TEST_CASE`; else `invalid`.

**b. Separate hypotheses** when the confirmed failure could be either "UCS sends the wrong request" or "the
connector behaves differently from the spec". If `test/requests/probe-<bug_id>.json` exists, run it first
(`TRANSCRIPT_ROOT={RUN_DIR}/rca/probes/r{ROUND}/<bug_id> bash $LIB run_request {RUN_DIR}/test/requests/probe-<bug_id>.json`)
and decide with its `probe.outcome_if` (response matches `H1`/`H2` → that hypothesis, the transcript is the live truth;
neither → decision row, proposed status `unresolved`, note `probe_inconclusive`, no brief). Otherwise send one direct
sandbox call built from the techspec's example request for that endpoint, bypassing UCS, with the `2.6d_test_exec.md`
`sandbox_fixture_curl` command (`--max-time` included). Base URL: `[connectors]` `<connector>.base_url` in
`config/development.toml`; auth headers as `${NAME}` placeholders expanded at call time (`env/load_secrets.sh`);
store the redacted transcript (2.6d transcript shape) at `rca/probes/r<N>/<bug_id>/<k>.json`. If the techspec
has no usable example, record `verified_live: needs_probe`, return `STATUS: PARTIAL` with
`NEXT: 2.6c_test_requests.md PROBE <bug_id>`, and route nothing for that bug. A bug already `needs_probe` in an
earlier `rca/r*.json` that still has no probe file (PROBE failed) → route on the 0a evidence alone, `confidence: low`,
decision row.

**c. Review bugs** (`source: review`) must demonstrate their observable consequence: run the finding's
`proposed_probe` (the `review/findings.json` item whose `id` equals the bug's `review_ref`): an existing case
through the driver, or a direct call as in b. Observed → `confirmed`. A claim about UCS behaviour that no existing case
exercises → render `proposed_probe` as one request file (`2.6c_test_requests.md` "## Request file schema — `{RUN_DIR}/test/requests/<case_id>.json`",
`case_id: probe-<bug_id>`, backend `grpcurl` or `curl_hs`, env `${NAME}` placeholders only, no `bind.`) at
`{RUN_DIR}/rca/probes/r{ROUND}/<bug_id>/probe.json`, and run it three times, one call each (tool parameter
`timeout: 600000`): `TRANSCRIPT_ROOT={RUN_DIR}/rca/probes/r{ROUND}/<bug_id> bash $LIB run_request <that file>`.
Runs showing `observable_consequence` decide as in the 0a table (3/3 `confirmed`, 1–2/3 `flaky`, 0/3 not observable).
Not observable → `verified_live: not_observable`, quote `file:line` (≤5 lines) as evidence, proposed status
`wont_fix`, note `not_observable` (the PR lists it under found-not-fixed); no brief.

## Phase 1: Locate the code

1. From the verify transcripts' `ucs_log_ref` / `hs_log_ref` take the error text, flow and connector, and search that
   fragment in `crates/integrations/connector-integration/src/connectors/<connector>.rs` and `…/<connector>/`
   (HS-side symptoms: `crates/` of the HS worktree named in `preflight.json`). Widen to `crates/types-traits/`,
   `crates/grpc-server/` only when the connector files have no match.
2. Plan item: look the file:line up in `code/*.json` `plan_item_map`; unmapped lines → note `unplanned`.
3. Introducing stage: `git for-each-ref --format='%(refname)' refs/grace/<run_id>/` (labels in `snapshots.tsv`),
   then `git diff <previous ref> <ref> -- <file>` to find the snapshot whose hunk created the lines.
4. `pre_existing`: `git blame --porcelain -L <a>,<b> -- <file>`. Commit `0000000000000000000000000000000000000000`
   (not committed yet) = written by this run (nothing is committed before the PR stage) → `false`; a commit with
   `git merge-base --is-ancestor <commit> <base_sha>` → `true`. Missing code (a branch that should exist) →
   `true` iff the enclosing function exists in `git show <base_sha>:<file>`.

## Phase 2: Stage walk (first wrong or missing stage = origin)

**2a. Test side first** — a bug can reach RCA misclassified:

| Origin | Verdict `wrong` when | Amend target |
|---|---|---|
| `ENV` | verify runs show ENV signals (`2.6d_test_exec.md` "## Phase 5: Classify each failed attempt (first match wins)" row 1) | `2.6a_test_env.md` REPAIR |
| `HS_CONFIG` | row 3 of that table: rollout/MCA read-back wrong | `2.6a_test_env.md` REPAIR |
| `REQUEST_GEN` | the sent request differs from the case inputs, the proto shape, or the HS API recipe (`2.5_e2e.md` "Phase 4: Run the real payment") | `2.6c_test_requests.md` AMEND `cases` |
| `TEST_CASE` | the case's expected value contradicts its cited oracle, inputs are untraceable, or dependency semantics are wrong | `2.6b_test_design.md` AMEND `cases` |
| `HARNESS` | harness / `global_suites` defect; the same request via direct grpcurl passes | none — report only, fix hunk under `crates/internal/integration-tests/` |
| `HS` | UCS never called with correct config (gate defaults false, missing `connector_config.rs` arm — `2.5_e2e.md` Phases 1–3), or HS maps a correct UCS response wrongly | `2.3a_plan.md` AMEND (`plan_items`: the `P-__hs__-NN` §9 item whose `anchor` matches, else `[]` = a new §9 item), then `2.3b_codegen_unit.md` AMEND (`units: ["__hs__"]`); brief `units` include `__hs__`, `fix[].repo: hs` |

**2b. Product stages, forward.** Establish the truth first (Rule 3), then give every stage a trace row:

| Stage | Artifact / ref | `wrong` or `missing` when | Amend target (scope) |
|---|---|---|---|
| `LINKS` | `links/merged.json`, `links/<unit_fs>.json` | the truth is in an official connector doc that is discoverable (linked from a URL already in the set, or on the same official docs host) and not in `links/merged.json`. You may WebFetch a cited or candidate URL; quote the sentence | `2.1_links.md` AMEND (`sections`: FOCUS topic) |
| `TECHSPEC` | spec section heading | the truth is in a fetched source (`source_*.md`, a URL in the set) or a live observation, and the spec is wrong or silent. Live-only truth → `LINKS` is `n/a`, `TECHSPEC` is `missing` | `2.2_techspec.md` AMEND (`sections`) |
| `PLANNER` | `plan/plan.md` § + `plan/plan.json` item | spec right; plan item wrong or missing (guards × `pm_arms`, contract decisions, HS parity, invariants) | `2.3a_plan.md` AMEND (`plan_items`) |
| `CODEGEN` | code file:line via `plan_item_map` | plan right; code differs from it | `2.3b_codegen_unit.md` AMEND (`units`) |

Evaluate every stage, including those after the origin: each stage whose artifact must change gets a
`fix[]` entry and an `amend_targets[]` entry, ordered upstream first. The origin is the first
`wrong|missing` row; stages before it are `correct`.

Trace row: `{stage, artifact, ref, verdict: correct|wrong|missing|n/a, evidence}` — `evidence` is a quote
(≤5 lines, redacted) plus its path.

**2c. GRACE self-fix.** When a trace shows the origin stage did what its instructions say and the defect lives in a
GRACE file (`grace/workflow/*`, `grace/rulesbook/*`, `.skills/*`), write `{RUN_DIR}/self-fixes/rca-<brief_id>.patch`
(unified diff against that file, a proposal, never applied) and `rca-<brief_id>.md` (problem, evidence: quoted
`file:line` + the trace rows, why the change prevents recurrence). The brief still routes the run's own fix;
`2.8_pr_run.md` lists both files under "GRACE self-fixes".

## Phase 3: Cluster

Bugs whose origin rows point at the same artifact ref (same spec section, same plan item, or overlapping
file:line ranges) share one root cause: `cluster_key = <origin>:<ref>` (e.g.
`CODEGEN:crates/integrations/connector-integration/src/connectors/braintree/transformers.rs:410-431`).
One brief per cluster; `brief_id = b<N>-<nn>`.

---

## Phase 4: Escalation (`{PREVIOUS_ORIGIN}`)

For a reappeared fingerprint the new origin must be exactly one stage upstream of the previous one:

| Previous | Required new origin |
|---|---|
| `CODEGEN` | `PLANNER` |
| `PLANNER` | `TECHSPEC` |
| `HS` | `PLANNER` |
| `TECHSPEC` | `LINKS` |
| `REQUEST_GEN` | `TEST_CASE` |
| `TEST_CASE` | `TECHSPEC` |
| `LINKS`, `ENV`, `HS_CONFIG`, `HARNESS` | none |

Walk only that upstream stage. `wrong|missing` → it is the origin. Otherwise, or when no upstream stage
exists, or when your suggested hunk reverses an earlier brief's `fix` (same file, `suggested_change`
restores that brief's `current`) → proposed status `unresolved` and a **withdraw recommendation** brief:
`withdraw: true` (the flag consumers key on), `fix: []`, amend target `2.3b_codegen_unit.md` AMEND for the unit,
`required_change` (prose) = return the unit to not_implemented and drop its suites from
`crates/internal/integration-tests/src/connector_specs/<connector>/specs.json`.
Recommend withdraw only if none of the unit's hunks are shared with another unit (compare `files_modified`
and `plan_item_map` across `code/*.json`); shared → `unresolved` without withdraw, decision row.

## Phase 5: Write briefs and the round result

**Brief** `{RUN_DIR}/rca/briefs/<brief_id>.json` (AMEND brief contract + RCA fields):
```
{brief_id, bug_ids:[], units:[<bug units ∪ every amend_targets[].scope.units; origin HS adds "__hs__">], origin, cluster_key,
 finding: "<what is observably wrong, ≤5 sentences>",
 evidence:[<run-dir or repo paths: verify transcripts, probes, sources>],
 required_change: "<one imperative sentence>",
 fix:[{repo: ucs|hs|run_dir, file, case_id|null, line_start, line_end, current: "<verbatim, ≤20 lines, redacted>",
       suggested_change: "<unified diff hunk>", rationale}],
 do_not_touch:[<paths, sections, plan items or units outside this cluster>],
 upstream_no_change: false,
 verified_live:{<bug_id>: confirmed},
 trace:[{stage, artifact, ref, verdict: correct|wrong|missing|n/a, evidence}],
 truth:{statement, source_ref: "<url + quote | rca/probes/... | hs:<file>:<line> | spec:<section>>"},
 amend_targets:[{agent_file, mode: AMEND|REPAIR, scope:{units:[], sections:[], plan_items:[], cases:[]}}],
 retest:{cases:[<the bugs' cases>], add_cases:[{kind, why}]},
 pre_existing:{<bug_id>: bool}, confidence: high|medium|low, withdraw: bool}
```
- `fix[].file`: `ucs` → repo-relative; `hs` → relative to the HS worktree; neither ever names a path under `grace/`.
  `run_dir` → the path the target scopes on: `{RUN_DIR}/test/cases.json` (`TEST_CASE`, 2.6b) or
  `{RUN_DIR}/test/requests/<case_id>.json` (`REQUEST_GEN`, 2.6c), one entry per `scope.cases` id with `case_id` set;
  and, with `case_id: null`, the upstream artifacts Rule 4 also requires a hunk for —
  `{RUN_DIR}/plan/plan.json` or `plan.md` (`PLANNER`, 2.3a), `{TECHSPEC_PATH}` (`TECHSPEC`, 2.2) and
  `{RUN_DIR}/links/<unit_fs>.json` (`LINKS`, 2.1).
- `mode: REPAIR` only for `2.6a_test_env.md`; every other target is `AMEND`. `HARNESS` → `amend_targets: []`.
- `withdraw: true` ⇔ `fix: []` (Phase 4); every other brief has a non-empty `fix`.
- `upstream_no_change` is always `false` here; the orchestrator owns passing a brief downstream after `NO_CHANGE`.
- `add_cases.kind` uses the case kinds of `2.6b_test_design.md` (e.g. `status_arm`, `negative_refusal`,
  `decline`, `id_consistency`, `capability_parity`); `why` names the exact behavior the case pins.
- `confidence`: `high` = confirmed 3/3 + truth quoted from a doc or probe + fix pinned to file:line; `medium` = two of
  those; `low` = fewer (add a probe-style regression case).

**Round result** `{RUN_DIR}/rca/r<N>.json` — one entry per cluster and one per unrouted bug:
```
[{bug_ids:[], origin|null, units:[], root_cause: "<one sentence>", confidence|null, brief_ref|null,
  cluster_key|null, verified_live:{<bug_id>: confirmed|flaky|invalid|not_observable|needs_probe},
  pre_existing:{<bug_id>: bool},
  proposed_status:{<bug_id>: fixing|flaky|invalid|wont_fix|unresolved},
  withdraw: bool}]
```
`needs_probe` bugs have no `proposed_status` entry (they stay `rca`). Write briefs first, `r<N>.json` last.

## Output

```
STAGE: rca
UNIT: -
STATUS: DONE | PARTIAL | BLOCKED | FAILED
OUTPUT: {RUN_DIR}/rca/r<N>.json
CHANGED_UNITS: [<units named by any brief>]
NEXT: <earliest amend target first, e.g. "2.2_techspec.md AMEND b3-01; 2.3b AMEND b3-02"> | "no routable bugs"
REASON: confirmed=<n> flaky=<n> invalid=<n> not_observable=<n> needs_probe=<n> briefs=<n> | ENV
```
`PARTIAL` = at least one bug is `needs_probe`; `FAILED` = an input file is missing or unreadable.
